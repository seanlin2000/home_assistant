Quantizing stores each weight in fewer bits than the usual 16. Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). The context cache and activations come on top. Trade-offs: some loss of quality, small at 4-bit and marked at 2-bit (reasoning and factual accuracy suffer most); faster generation, because inference is limited by memory bandwidth; careful methods (GPTQ, AWQ, importance-weighted quantization) reduce the loss. Wrong memory figures are an error.

ASSISTANT: Quantizing means storing each weight in fewer bits instead of the full 16 bits, usually by grouping weights into blocks and saving a small scale factor per block, so the model keeps roughly the same shape but the numbers are rounded to a coarse grid.

For 70 billion weights, that's 70 billion times bits per weight divided by eight. In 4-bit, about 35 gigabytes. In 2-bit, about 17.5 gigabytes. Full 16-bit precision would be around 140 gigabytes. Add a bit for activations, cache and overhead, so real footprints run a little higher.

The trade-offs: 4-bit is usually a mild accuracy hit, often a small rise in perplexity, and it fits on consumer hardware. Two-bit is aggressive and can noticeably degrade reasoning, code and long-context tasks, and it can be slower per token because unpacking overhead outweighs the memory savings.
