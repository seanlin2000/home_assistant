ASSISTANT: A language model's "weights" are a huge list of floating-point numbers — the trained knobs that determine how it processes text. Quantization means replacing each of those high-precision numbers with a lower-precision one, so fewer bits are needed to store and move each value. Full-precision training usually uses sixteen or thirty-two bits per weight; quantizing to four bits stores each weight using only a quarter of that, and two bits an eighth. You do this by grouping weights into blocks, figuring out the range of values in each block, and snapping every weight to the nearest point on a coarse grid of values — the grid has sixteen slots at four bits, only four slots at two bits.

For a 70-billion-parameter model, the math is simple: multiply the parameter count by bits per weight and divide by eight to get bytes. At 4-bit precision that works out to about 35 gigabytes of weight storage. At 2-bit, about 17.5 gigabytes — half as much again. For comparison, the same weights at 16-bit precision would be 140 gigabytes, which is why quantized versions can fit on a single workstation GPU while full precision needs datacenter hardware. In practice the on-disk size is close to these numbers, though running the model also needs extra memory for the activations and, with 4-bit schemes like GPTQ or AWQ, small per-group scale factors.

The trade-offs come down to how coarse that grid is. The dropped precision is noise added on top of the model's weights, and the model has to tolerate it. At 4-bit you lose a small amount of accuracy — benchmarks usually drop by a point or so — and many modern methods like GPTQ and AWQ keep 4-bit close enough to full precision that it's often called the sweet spot for running large models. At 2-bit the grid is very coarse, and the model genuinely forgets some of what it learned: instruction following gets worse, longer and more complex reasoning degrades noticeably, and it can start producing more errors or nonsensical outputs. You can also see more dramatic failure modes — the model becomes brittle, small inputs push it into bad behavior, and calibration quality matters a lot.

There are other practical costs too. Quantization needs a calibration step, where you run representative sample data through the model to figure out the right scale for each group; if the calibration data doesn't match your actual use, quality suffers. Some layers are more sensitive than others, so good schemes leave a few of them at higher precision. And because the operations no longer match hardware that's optimized for 16-bit math, you can end up needing specialized kernels to actually get the speedup that the memory savings suggest. So the rule of thumb: 4-bit is a safe default for a 70B model you want to run on consumer hardware, while 2-bit is usually reserved for situations where memory is the hard constraint and you can accept a visibly dumber model.
