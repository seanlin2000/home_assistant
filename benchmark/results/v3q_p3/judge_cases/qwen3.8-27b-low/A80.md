Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). ASSISTANT: So the short version: quantization means storing each weight with fewer bits than the model was originally trained with, trading some numerical precision for a smaller footprint.

A 70-billion-parameter model with each weight stored at full 16-bit precision takes about 140 gigabytes of memory just for the weights. Drop to 4-bit and that's 35 gigabytes. Go all the way to 2-bit and it's 17.5 gigabytes. The math is just parameters times bits per weight, divided by eight to get bytes, then into gigabytes.

The trade-offs. The core one is that you're throwing away information. A 16-bit floating point number can represent roughly 65 thousand distinct values; a 4-bit number can only represent 16, and a 2-bit number only 4. So each weight gets rounded to the nearest representable value, and that rounding error accumulates across billions of weights and can degrade the quality of the model's output. In practice, 4-bit quantization using methods like AWQ or GPTQ usually keeps a model close to its original quality, though you'll often see a small drop on tasks like math, code generation, or long-form consistency. 2-bit is a different story: it's aggressive enough that quality degrades noticeably in most cases, and it's generally only practical if you're doing it with a very careful method and you can tolerate worse results, or if you're doing something like speculative drafting where the quality bar is lower.

There are a couple of other things worth mentioning. First, the 35 or 17.5 gigabyte number is just the weights. You still need room for activations and the KV cache during inference, so a real deployment needs more memory than the raw weight size suggests. Second, quantization isn't free at run time: dequantizing weights back to higher precision on the fly adds a little overhead, though on modern hardware with the right kernels the compute penalty is usually small compared to the memory savings, which are the whole point.

One practical note: when people say "I ran a 70B model on a workstation," they almost always mean a 4-bit quantization, because that's the version that fits in, say, 48 gigabytes of RAM or a couple of high-memory GPUs. The 2-bit version fits in less, but at a quality cost that usually isn't worth it unless you really need the footprint.
