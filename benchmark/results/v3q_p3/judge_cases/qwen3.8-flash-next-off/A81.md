Reference sketch (what a correct answer must contain):
The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. Websites the assistant then fetches see the IP address and the requests. What stays local: the audio and transcription if speech is processed locally, the full conversation and history, the model's reasoning and answers, and anything never put into a query. Minimizing exposure: keep personal details out of queries (write queries from the question, not the whole conversation), search only when needed, cache results, use a privacy-focused provider or a self-hosted metasearch proxy such as SearXNG, route through a VPN for IP privacy, and check the provider's data-retention terms.

ASSISTANT: Short version: running the model locally protects your prompts and your weights, but the moment a tool call fires off a web search, whatever text went into that tool call leaves your machine, along with your IP address and your API key. The search provider becomes a window into your reasoning, because search queries generated by a model are often near-verbatim fragments of what you asked it.

What stays local
Your model weights, your full conversation context, the system prompt, any files or documents you fed in, intermediate chain-of-thought text, and everything the model does with the results after they come back. Nothing about your documents is transmitted unless the model decides to build a query that quotes them — which it frequently does.

What actually gets transmitted
Each search call is an HTTPS request carrying:

- The query string itself. This is the big one. Models routinely include proper nouns, file names, ticket numbers, product names, error messages, code snippets, and sometimes whole sentences copied from your local context. A query like "how do I fix error 0x80070005 in AcmeCorp payroll export logs" tells the provider a lot about you even though it looks technical.
- Your API key or account identifier, which links every query to your billing account and therefore to your name, postal address, and payment details on file with the provider. Brave's own privacy notice is explicit that customers must supply payment and postal details for all plans.
- Your IP address, User-Agent string, request timestamps, and request metadata such as country, language, SafeSearch settings, pagination offsets, and result-count parameters. Brave documents that it processes IP addresses and authentication tokens for billing, troubleshooting, and abuse prevention.
- On some providers, extra data depending on the endpoint. Extraction or "crawl" endpoints send a URL you chose, which reveals what you were reading. Some RAG-oriented providers also offer to return pre-extracted page text, which means they fetch pages on your behalf and their crawler's identity is visible to those sites.
- If you render results in a browser or fetch linked pages yourself, the destination sites see your IP and possibly a referer header — that's a separate disclosure from the search provider.
