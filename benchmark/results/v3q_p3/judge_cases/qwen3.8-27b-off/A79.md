Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

GPUs are so effective at AI inference because they're built around massive parallelism. A modern GPU like an H100 or B200 has tens of thousands of small cores — CUDA cores for floating point, tensor cores specifically for matrix math. Neural network inference is dominated by exactly the kind of work these units love: multiplying and adding huge matrices of numbers in lockstep. A single transformer layer might involve a matrix multiply with billions of parameters, and a GPU can chew through that in parallel rather than serially.

There's also memory bandwidth. Inference is often more memory-bound than compute-bound — you have to load all those weights from high-bandwidth memory into the compute units. GPUs pair their many cores with very wide, fast memory buses (HBM3e on current chips), which keeps the arithmetic units fed. A CPU, by contrast, has far fewer cores and much narrower memory bandwidth relative to its peak math throughput, so it stalls waiting for data.

Now the three categories you asked about:

GPUs are general-purpose parallel processors. They can do training, inference, graphics, scientific computing, video encoding — anything that maps onto a lot of parallel threads. That flexibility is the trade-off: they burn more power per useful operation than a chip designed to do only one thing, and their instruction set has overhead for things like branching, memory ordering, and generic register files that aren't needed for a fixed workload.

ASICs — application-specific integrated circuits — are custom silicon built for one job. TPU is the canonical example, but so are Google's TPU generations, Cerebras' wafer-scale engine, Groq's LPU, and various hyperscaler in-house chips. They throw away generality to get more of what they need: dedicated matrix units, huge on-chip SRAM instead of relying on HBM, custom dataflow that streams activations through the chip without round-tripping to memory, and often fixed-point or low-precision arithmetic paths tuned for the precision formats actually used in inference (INT8, FP8, INT4).

Specialized inference processors sit somewhere between those two. They're not as locked down as a pure ASIC but are far more purpose-built than a GPU. Examples include NPU-style accelerators from AMD (XDNA), Intel (Gaudi for training, but also their Arc iGPU NPUs and the newer Falcon Shores), and mobile SoC vendors like Apple and Qualcomm who bake inference engines into consumer chips. These often target efficiency per watt at the edge rather than raw throughput.
