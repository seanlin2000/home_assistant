# Turn 1

USER: Why can a 16 GB GPU sometimes run an MoE model with 30 billion total parameters, but not necessarily a 30 billion parameter dense model? Explain the difference between active parameters and the memory required to store the model.

ASSISTANT: A 16 GB GPU can run a Mixture-of-Experts (MoE) model with 30 billion *total* parameters because MoE models only activate a small fraction of those parameters for each inference step, whereas dense models require all 30 billion weights to be loaded into memory simultaneously.

In a dense model, the VRAM requirement is calculated by multiplying the total parameter count by the size of each parameter (usually 4 bytes or 8 bytes) plus overhead for activations and gradients. This means a 30B dense model needs roughly 120 GB of VRAM if weights are 4 bytes per parameter, far exceeding a 16 GB card.

In contrast, an MoE model like Gemma-2b-mix or Mixtral has millions of "expert" parameters split across many groups. During a single forward pass, the model randomly selects only one or two experts (e.g., 45 million parameters) to process the input. The total parameter count remains high because all experts are stored on the card for future use, but the active memory usage during inference is drastically lower, often comparable to running a much smaller dense model. This architecture allows you to fit a model with billions of *total* parameters on hardware that couldn't run a dense model of that same weight count.
