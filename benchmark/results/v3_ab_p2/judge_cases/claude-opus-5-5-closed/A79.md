Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

# Exchange 1

USER: Why are GPUs so effective at AI inference? Explain the differences between GPUs, ASICs, and specialized inference processors. Under what circumstances could a specialized chip outperform an NVIDIA GPU?

ASSISTANT: GPUs are good at AI inference because running a neural network is mostly huge matrix multiplications, which split into thousands of identical small calculations a GPU can do at once, and because GPUs pair that with very fast high-bandwidth memory. For large language models, memory bandwidth often matters more than raw math, since every generated word means reading the model's weights. NVIDIA's other big edge is software: CUDA and its libraries mean nearly every model runs well on day one. An ASIC is a chip built for one fixed job. Specialized inference processors, like Google's TPU, Groq's chips, Cerebras's wafer-scale engine or transformer-only designs, are ASICs aimed at neural networks; they drop general-purpose parts and spend the silicon on matrix units, on-chip memory and data movement. A specialized chip can beat an NVIDIA GPU when the workload is huge and stable, such as one popular model served to millions of users; when the lowest latency per user matters, where keeping weights in on-chip memory pays off; or when power and cost per token dominate. The risk is that models change faster than chips, and a narrow design can be left behind.
