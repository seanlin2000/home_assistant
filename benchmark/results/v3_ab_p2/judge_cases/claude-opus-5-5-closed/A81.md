Reference sketch (what a correct answer must contain):
The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. Websites the assistant then fetches see the IP address and the requests. What stays local: the audio and transcription if speech is processed locally, the full conversation and history, the model's reasoning and answers, and anything never put into a query. Minimizing exposure: keep personal details out of queries (write queries from the question, not the whole conversation), search only when needed, cache results, use a privacy-focused provider or a self-hosted metasearch proxy such as SearXNG, route through a VPN for IP privacy, and check the provider's data-retention terms.

# Exchange 1

USER: If I run a language model locally on my computer but use an external web-search API, what information can the search provider see? Explain what stays local, what gets transmitted, and how I can minimize data exposure.

ASSISTANT: The search provider sees your search queries and everything that travels with them, but not your conversation or your model. What stays local: your prompts, the conversation history, the model's reasoning, files and personal data on your machine, and the final answer, unless the model copies them into a query. What gets transmitted: the exact query text the model writes, which can leak context like your name, address or health details if the model folds them in; your IP address, which reveals rough location; your API key, which ties every query to your account and payment details; and timing and volume patterns. And if your assistant then fetches the result pages, each of those websites also sees your IP and which pages you opened. To minimize exposure, instruct or filter the model to write short, generic keyword queries and strip personal details before sending; choose a provider with a clear no-logging or short-retention policy; route traffic through a VPN or proxy if your IP matters; skip searching for things the model already knows; or self-host a meta-search engine like SearXNG, though the engines behind it still see your server's address.
