# Exchange 1

USER: Imagine I want to build a private, locally hosted voice assistant that can answer general questions, search the web, control smart-home devices, and have natural conversations. I have a $1,000 hardware budget. Propose an architecture, explain the components, identify the biggest limitations, and prioritize what I should build first.

ASSISTANT: I would build it in layers. The brain is a small to mid-size language model running on one machine, such as a recent Mac mini with plenty of unified memory, or a mini PC with a decent graphics card. Around it you need speech to text, such as Whisper, and a text to speech voice, run through a voice framework like Home Assistant's Wyoming protocol. Home Assistant also handles smart home control, and a web-search tool gives the model current information. Prices change, so check that your chosen machine fits the budget. The biggest limitations are model size, because a local model is much weaker at hard reasoning than the large cloud models, along with response speed, since longer answers can feel slow, and search quality, since the model needs a good search tool and discipline about trusting web text. Also, good far-field microphones and speakers take a share of your budget. For build order, start with Home Assistant and basic voice commands for lights. Then add speech recognition and speech output, then the local model for conversation, and finally web search and tuning.
