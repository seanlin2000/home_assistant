Quantizing stores each weight in fewer bits than the usual 16. Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). The context cache and activations come on top. Trade-offs: some loss of quality, small at 4-bit and marked at 2-bit (reasoning and factual accuracy suffer most); faster generation, because inference is limited by memory bandwidth; careful methods (GPTQ, AWQ, importance-weighted quantization) reduce the loss. Wrong memory figures are an error.

# Exchange 1

USER: What does it mean to quantize a 70-billion-parameter language model to 4-bit or 2-bit precision? How much memory would the weights require in each case, and what trade-offs does quantization introduce?

ASSISTANT: Quantizing means storing each of the model's weights with fewer bits, rounding them to a coarser set of values, so the model takes less memory and runs faster. Normally weights are sixteen bits each. For seventy billion parameters, at sixteen bits that is about one hundred forty gigabytes. At four bits, each weight takes half a byte, so roughly thirty-five gigabytes. At two bits, a quarter of a byte each, so roughly seventeen and a half gigabytes. Those are the weights alone. Real files run a bit larger because some parts stay at higher precision, and you also need memory for the conversation's context cache. The tradeoff is accuracy. Four-bit is usually close to the original, with a small drop in quality that most people barely notice. Two-bit loses much more, so you can see worse reasoning, more mistakes, and weaker handling of unusual tasks, though clever methods reduce the damage. In return you get a model that fits on far cheaper hardware and often generates text faster, since less data needs to move per token.
