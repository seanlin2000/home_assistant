Quantizing stores each weight in fewer bits than the usual 16. Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). # Exchange 1

USER: What does it mean to quantize a 70-billion-parameter language model to 4-bit or 2-bit precision? How much memory would the weights require in each case, and what trade-offs does quantization introduce?

ASSISTANT: Quantizing means storing each of the model's weights with fewer bits, trading some precision for a much smaller size. A seventy-billion-parameter model normally uses sixteen bits per weight, which is about one hundred forty gigabytes. At four bits, each weight takes half a byte, so the weights need roughly thirty-five gigabytes. At two bits, a quarter of a byte, they need about seventeen and a half gigabytes. In practice the real files run a bit larger, since some layers stay at higher precision and the scaling information takes space, and you also need extra memory for the context cache while the model runs. The trade-offs are these. Quality drops as bits drop. Four-bit methods usually lose only a small amount of accuracy, while two-bit models often degrade noticeably, with weaker reasoning, coding, and factual recall, and more errors in long outputs. Smaller weights also load faster and can run faster, since generation is often limited by memory bandwidth, and they let a large model fit on hardware that otherwise couldn't hold it. Clever schemes that quantize important weights more carefully help close the quality gap.
