Reference sketch (what a correct answer must contain):
The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. Websites the assistant then fetches see the IP address and the requests. What stays local: the audio and transcription if speech is processed locally, the full conversation and history, the model's reasoning and answers, and anything never put into a query. Minimizing exposure: keep personal details out of queries (write queries from the question, not the whole conversation), search only when needed, cache results, use a privacy-focused provider or a self-hosted metasearch proxy such as SearXNG, route through a VPN for IP privacy, and check the provider's data-retention terms.

# Exchange 1

USER: If I run a language model locally on my computer but use an external web-search API, what information can the search provider see? Explain what stays local, what gets transmitted, and how I can minimize data exposure.

ASSISTANT: The model, its weights, your full conversation, your files and the model's reasoning all stay on your machine. What leaves is each search query the model writes, sent over an encrypted connection to the search provider. The provider sees the query text, your IP address and so your rough location, your API key, which ties every query to your account and billing details, and the timing and volume of your searches. Queries can be revealing, because a model often folds in context like your neighborhood, a health issue or a person's name. If your system also fetches the result pages, those websites see your IP address too. To minimize exposure, have the model write short, generic queries with personal details stripped out; search only when a question needs it, not on every turn; choose a provider with a no-logging or zero-retention policy; route search and page fetches through a VPN or proxy; or run a self-hosted metasearch engine like SearXNG, which spreads queries across engines without an account.
