Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

**Why GPUs work so well for inference**

Almost all of a modern model's compute is matrix multiplication: attention and feed-forward layers are big multiply-accumulate operations over weight matrices. That's embarrassingly parallel — millions of independent multiply-adds with no branching — which is the same workload GPUs were invented for rendering graphics. NVIDIA added tensor cores specifically to do small matrix multiplies at high rate, so a single instruction drives a dense grid of arithmetic.

The second reason matters more than raw flops, and it's memory. During token generation, you have to read essentially every weight once per token. For a 70-billion-parameter model in 16-bit, that's roughly 140 gigabytes of data moved per token generated. So inference is bottlenecked by memory bandwidth far more than by arithmetic. H100 and H200 parts sit around three to five terabytes per second of high-bandwidth memory, which is why NVIDIA spends so much of its design effort there rather than on more flops. One analysis I read put it this way: architectures are competing over data movement, not just multiplication.

The third reason is unglamorous but decisive: CUDA, cuDNN, TensorRT-LLM, FlashAttention, paged attention, quantization tooling. A chip that's 20 percent slower in theory but runs every model on day one with mature kernels beats a faster chip where your custom kernel doesn't compile.

**How the three categories differ**

A GPU is a generalist: many cores, wide caches, hardware schedulers that handle unpredictable branching and dynamic shapes, plus a huge software ecosystem. It does training, fine-tuning, batch inference and interactive serving on the same silicon. The cost of that flexibility is dead area on the die — graphics units, texture logic, cache hierarchy, scheduling hardware — and the price of that silicon shows up in the bill. One estimate puts an H200's manufacturing cost near five thousand dollars, with HBM memory alone accounting for roughly 44 percent of it, more than the logic die itself.

An ASIC is the opposite bet: fixed functionality etched in, no scheduler flexibility, no unused blocks. Google's TPU and Amazon's Trainium are the mature examples — matrix engines tuned for transformer layers, simpler interconnect, compiler-first toolchains. They lose on generality and gain on throughput per watt and cost per token.
