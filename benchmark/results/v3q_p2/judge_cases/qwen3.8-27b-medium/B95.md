ASSISTANT: Great project — and the good news is that as of 2026 this stack is genuinely practical. Here's how I'd think about it.

The architecture breaks down into a pipeline with five stages. First, a wake-word detector like openWakeWord listens continuously for a phrase like "okay assistant" — it's tiny and runs on a basic CPU. Second, speech-to-text, and the community standard is faster-whisper, which converts your voice to text locally. Third, a local LLM — run through Ollama — interprets what you said, maintains conversational context, and decides whether to answer, call a tool, or both. Fourth, a tool layer: the LLM makes function calls against Home Assistant's API for smart-home control, and optionally against a search tool. Fifth, text-to-speech, where Piper is the go-to because it runs in real time on a plain CPU with natural-enough voices. Home Assistant 2026 has native integrations for all of this — the Whisper and Piper add-ons over its Wyoming protocol, and Ollama is built straight into the voice pipeline UI now, so you're not writing much glue code yourself.

On hardware, I'd spend your thousand dollars roughly like this. The brain: a Mac mini M5 with 24 gigs of RAM, about six hundred dollars. Apple Silicon is currently the sweet spot for local inference — Ollama's MLX support makes it up to ninety percent faster than comparable CPUs, and unified memory lets it run Whisper-large and a solid eight-to-thirty-billion parameter model like Qwen3 at once, with end-to-end latency in the one-to-two second range that actually feels conversational. The smart home: a small Intel N100 mini-PC for one fifty to two hundred dollars to run Home Assistant, keeping it separate so a reboot of your AI box never takes your lights down.
