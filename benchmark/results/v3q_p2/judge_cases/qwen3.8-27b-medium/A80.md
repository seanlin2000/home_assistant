ASSISTANT: Quantizing a model means replacing each weight, which is normally stored as a full-precision number with many bits, with a coarser representation that uses fewer bits per weight. Instead of storing every weight as a 16-bit floating-point number, the model groups weights together, finds a representative value or scale for each group, and stores only the small index or offset for each weight. So at 4-bit precision, each weight is stored as a number with only 16 possible values instead of roughly 65,000, and at 2-bit it drops to just 4 possible values per weight.

The memory math is straightforward. Each bit is one-eighth of a byte, so a 70-billion-parameter model at 4-bit needs about 35 gigabytes of memory for the weights alone. At 2-bit, that's roughly 17.5 gigabytes. For comparison, the same model at 16-bit would need about 140 gigabytes, which is why quantized versions are what make models like this fit on a single consumer GPU or even run on powerful laptops.

The trade-offs are mostly about quality versus efficiency. At 4-bit, modern methods like group-wise quantization with scaling factors hold up remarkably well, and most people find the model still answers well with only a small loss in accuracy, sometimes under a percent on standard benchmarks. It's become the de facto standard for local deployment. Dropping to 2-bit is much more aggressive, and you start to see real degradation, with more frequent nonsensical or repetitive output, weaker instruction following, and noticeably worse performance on tasks that rely on precise reasoning or knowledge. The model may also become more sensitive to prompts and edge cases it handled fine in higher precision.

There are a couple of secondary costs worth mentioning. Quantized models can be slightly slower to load because of the extra work to unpack weights during inference, though once running they're usually faster in practice because the smaller weights fit better in the memory bandwidth that's often the real bottleneck. And quantization is lossy and mostly irreversible, so if you need the full-quality model for fine-tuning or training, you'd want the original weights. The practical rule of thumb is that 4-bit is a great sweet spot for most people, while 2-bit is mostly useful when you genuinely don't have the memory for 4-bit and can tolerate the quality hit.
