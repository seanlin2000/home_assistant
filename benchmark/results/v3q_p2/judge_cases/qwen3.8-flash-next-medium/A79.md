Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

Specialized chips win when they hard-wire one assumption — where the model's weights live — and give up everything else.

Why GPUs work so well

A transformer's forward pass is a sequence of large matrix multiplies plus some elementwise operations. That's a perfectly regular, embarrassingly parallel computation, so a GPU's structure fits it almost exactly: thousands of simple cores running in lockstep, plus dedicated "tensor cores" that do a small matrix multiply in hardware, and increasingly low-precision modes like FP8 and FP4 that let you do more math per watt and per byte of memory.

The subtlety is that inference has two very different phases. Prefill, where the model processes your whole prompt at once, is compute-bound — it saturates the arithmetic units, which is the regime GPUs were designed for. Decode, where the model generates one token at a time, is memory-bound. On every single generated token, the hardware has to read essentially the entire model's weights again.

That's the wall, and the arithmetic makes it vivid. A 70-billion-parameter model stored at 8 bits per weight is about 70 gigabytes. An H100's high-bandwidth memory moves roughly 3.35 terabytes per second, which as a theoretical ceiling works out to somewhere around 48 tokens per second, and an H200 at 4.8 terabytes per second gets you maybe 68. Published single-stream GPU numbers for 70-billion-class models sit in the 50-to-150-tokens-per-second range, right near that ceiling. So the GPU is not being wasteful; it is being limited by physics, by the fact that DRAM sits on the other side of a package.

The way GPUs cheat that limit is batching. If you keep 64 requests in flight, you read those weights once and do useful arithmetic for 64 streams, so throughput per dollar climbs dramatically even though each individual user's tokens-per-second stays similar. GPUs also benefit from software: FlashAttention, paged attention, KV-cache optimization, speculative decoding, TensorRT-LLM. That stack is a genuine moat, and it also means a new model architecture is supported on day one because the chip is programmable.

GPUs, ASICs, and inference-specific chips

A GPU is a general-purpose parallel processor with a hardware scheduler, caches, and an instruction stream you can rewrite at runtime. You pay for that flexibility in wasted area, wasted energy moving instructions, and nondeterministic timing.

A tensor-processing ASIC like Google's TPU trades some of that flexibility away. It uses systolic arrays, which are essentially plumbing for multiplying matrices, and it relies on a compiler to lay out the whole computation in advance. That's very efficient for large, static tensor workloads, particularly at scale in a datacenter with a well-defined software stack, and it can be better on throughput-per-dollar. What it gives up is the ability to handle odd control flow or a new architecture before someone updates the compiler.

Inference-only chips go further again. Groq's LPU keeps the model's weights in on-chip SRAM rather than external memory, and it executes deterministically, with the compiler scheduling not just the arithmetic but the communication between chips. No memory fetch per token, no scheduler jitter. Cerebras takes the same idea to an extreme: its WSE-3 is a whole 300-millimeter wafer, about 46,000 square millimeters of silicon with 900,000 cores, 44 gigabytes of on-chip SRAM and roughly 21 petabytes per second of on-chip memory bandwidth. That is thousands of times the bandwidth of an H100, which is why single-stream decode gets so fast. And a chip like Taalas's HC1 burns a specific model into the silicon itself, which is the fastest and least flexible option there is.
