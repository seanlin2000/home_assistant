Reference sketch (what a correct answer must contain):
The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. Websites the assistant then fetches see the IP address and the requests. What stays local: the audio and transcription if speech is processed locally, the full conversation and history, the model's reasoning and answers, and anything never put into a query. Minimizing exposure: keep personal details out of queries (write queries from the question, not the whole conversation), search only when needed, cache results, use a privacy-focused provider or a self-hosted metasearch proxy such as SearXNG, route through a VPN for IP privacy, and check the provider's data-retention terms.

# Exchange 1

USER: If I run a language model locally on my computer but use an external web-search API, what information can the search provider see? Explain what stays local, what gets transmitted, and how I can minimize data exposure.

ASSISTANT: If the model runs locally, your prompts, conversation history, files and voice stay on your machine unless something sends them out. What leaves is only the search query that your software chooses to send, plus ordinary connection details. The search provider can see the query text, your IP address, the time, your browser or client identifier, any API key tied to your account, and possibly cookies. If the model writes queries from your whole conversation, a query can leak personal details, such as your name, location or health question, because it is a distilled version of what you asked. The provider can also log queries and link them to you through your key or IP address. Pages you then fetch reveal your IP address to those websites. To limit exposure, do the following. Have the model write short, generic queries and strip names, addresses and private details before sending. Use a provider with a no-logging policy, or a self-hosted metasearch engine. Route traffic through a VPN. Avoid sending cookies. Use separate keys not tied to your identity. And review the logs of outgoing queries so you see exactly what goes out.
