USER: Imagine I want to build a private, locally hosted voice assistant that can answer general questions, search the web, control smart-home devices, and have natural conversations. I have a $1,000 hardware budget. Propose an architecture, explain the components, identify the biggest limitations, and prioritize what I should build first.

ASSISTANT: Here is the architecture I would propose. The voice pipeline has four parts: a wake-word detector, speech-to-text such as Whisper, a language model, and text-to-speech such as Piper, all tied together by a framework like Home Assistant with its Wyoming protocol, which also handles smart-home control. The language model runs on a local server, such as llama.cpp, and calls tools for web search, weather and device control. For a thousand dollars, the best choice is probably a used or new Mac mini with at least 32 gigabytes of unified memory, or a small PC with a used 24-gigabyte GPU. Add a cheap microphone speaker, like a ReSpeaker or a small satellite device in each room. The biggest limitations are model quality, since a model small enough to run on that budget will reason and know less than the cloud models; response speed; speech recognition accuracy in noisy rooms; and web search, which needs an outside API and so is not fully private. My build order would be: first, get Home Assistant controlling your devices with local voice commands; second, add speech-to-text and text-to-speech with a wake word; third, add the language model for conversation; and last, add web search and other tools.
