Reference sketch (what a correct answer must contain):
An API is an interface one program offers to others (a web search service's HTTP endpoint, for example). A tool, for an LLM, is a function the model may ask to call, described by a name, a description and an argument schema; the surrounding software runs it and hands back the result. An MCP server speaks the Model Context Protocol, an open standard for offering tools (and resources and prompts) to any compatible client, and often wraps one or more APIs. Architecture: the model served locally; an agent loop that sends the conversation and tool list, runs any tool call, returns the result and asks again; an MCP server with a search tool (calling a search API or SearXNG) and a page-fetch tool (download, extract the main text, cap its size); summarizing done by the model itself from the returned text. Safeguards: a cap on tool rounds, timeouts, treating fetched text as untrusted (prompt injection), and caching.

# Exchange 1

USER: Explain the difference between an API, an MCP server, and a software tool. If I wanted to give a local LLM the ability to search the web, retrieve webpages, and summarize them, how would you architect the system?

ASSISTANT: An API is a general interface that one program offers so another can request things, like a weather service you call over the internet. A software tool, in the language-model sense, is a function the model is allowed to call, described by a name, a purpose and its arguments, such as search the web. An MCP server, short for Model Context Protocol, is a standard way to package and expose tools to any compatible model application, so you do not write custom glue code for each one. Often an MCP tool wraps an API inside. To give a local model web search, page retrieval and summarizing, I would run a local model server, then an agent loop or chat application that talks to it. Next, I would write one MCP server with two tools: a search tool that calls a search API or a self-hosted search engine, and a fetch tool that downloads a page and extracts the main text. The model decides when to call them, and the loop feeds results back. Summarizing is just the model itself reading the text. I would trim long pages to fit the context window, mark fetched text as untrusted so it cannot give the model instructions, and limit how many calls happen per question.
