Quantizing stores each weight in fewer bits than the usual 16. Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). The context cache and activations come on top. Wrong memory figures are an error.

# Exchange 1

USER: What does it mean to quantize a 70-billion-parameter language model to 4-bit or 2-bit precision? How much memory would the weights require in each case, and what trade-offs does quantization introduce?

ASSISTANT: Quantizing means storing each weight with fewer bits, trading a little accuracy for a much smaller model. A 70-billion-parameter model normally uses sixteen bits, or two bytes, per weight, so about 140 gigabytes. At 4 bits, that is half a byte per weight, so roughly 35 gigabytes. At 2 bits it is a quarter byte per weight, so roughly 17.5 gigabytes. Those are weights only. Real files run a bit larger, because quantization schemes keep scaling factors and some layers at higher precision, and you also need memory for the key-value cache and activations that grows with context length. The trade-offs are these. Smaller size means the model fits on cheaper hardware, and since inference is memory-bandwidth-limited, it often runs faster too. The cost is lost precision. Four-bit quantization is usually a mild loss, often barely noticeable for chat. Two-bit quantization is much more damaging, with worse reasoning, more errors in math and code, and weaker factual recall, though newer methods soften this. Larger models tolerate quantization better than small ones, so a heavily quantized 70-billion model can still beat a smaller full-precision one.
