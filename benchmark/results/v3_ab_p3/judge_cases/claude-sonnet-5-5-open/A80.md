Quantizing stores each weight in fewer bits than the usual 16. Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). The context cache and activations come on top. Trade-offs: some loss of quality, small at 4-bit and marked at 2-bit (reasoning and factual accuracy suffer most); faster generation, because inference is limited by memory bandwidth; careful methods (GPTQ, AWQ, importance-weighted quantization) reduce the loss. Wrong memory figures are an error.

# Exchange 1

USER: What does it mean to quantize a 70-billion-parameter language model to 4-bit or 2-bit precision? How much memory would the weights require in each case, and what trade-offs does quantization introduce?

ASSISTANT: Quantizing means storing each of the model's weights using fewer bits. Normally weights are sixteen-bit numbers, and quantization rounds them to four-bit or two-bit values, with small scaling factors to keep the range sensible. For seventy billion parameters, the math is simple. At sixteen bits that is about one hundred forty gigabytes. At four bits it is about thirty-five gigabytes, and at two bits about seventeen and a half gigabytes. Real files run somewhat larger, since some layers stay at higher precision and the scales add overhead, so think roughly forty gigabytes for a four-bit version. The trade-off is quality. Four-bit usually loses only a little accuracy, and most people find it a good balance. Two-bit loses noticeably more, with weaker reasoning, more errors, and worse instruction following, though clever methods soften that. In exchange you get a smaller memory footprint, faster generation, since memory speed is the bottleneck, and the ability to run on hardware you actually own.
