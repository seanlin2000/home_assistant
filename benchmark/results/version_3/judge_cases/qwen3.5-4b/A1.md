# Turn 1

USER: Why can a 16 GB GPU sometimes run an MoE model with 30 billion total parameters, but not necessarily a 30 billion parameter dense model? Explain the difference between active parameters and the memory required to store the model.

ASSISTANT: The key difference lies in how Memory-of-Estate (MoE) models handle computation versus storage. A MoE model doesn't process all 30 billion parameters for every single input; instead, it only activates a small subset—often around 6 to 12 billion—at inference time. This means that while the model has a massive total parameter count on paper, the VRAM required to actually run the forward pass is much lower than you'd think because it's only calculating with the active parameters.

Conversely, a dense model (like Llama-3-8B or Mistral-7B) activates every single one of its parameters for every token it processes. This means the memory footprint for running inference is directly proportional to the total parameter count multiplied by the size of each parameter. So, while a 16GB card might be able to fit a dense model with roughly 30 billion parameters, that same card would struggle significantly with a MoE model claiming that same number because you'd have to account for the memory needed to store the entire, massive pool of weights, even though you only "use" a fraction of them at once.
