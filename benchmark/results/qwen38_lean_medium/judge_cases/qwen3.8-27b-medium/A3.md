# Exchange 1

USER: Someone says that because an MoE model only activates 4 billion parameters per token, a 4 GB GPU should be enough to run it. Is that correct? Explain exactly why or why not.

ASSISTANT: No, that's not correct — it confuses two different resources.

The "4 billion parameters per token" number is a statement about compute, not memory. It tells you roughly how many floating point operations the model does for each token, which is why MoE models can be fast and relatively cheap to run. But the number of parameters a GPU has to hold in memory is the model's total parameter count, and in a real mixture-of-experts model that is much bigger than the active count.

Here's why. At any given token, the router looks at that token's input and decides which experts get used. That decision is different token by token and effectively unpredictable in advance, so the model can't just keep the popular experts around — every expert's weights have to be sitting in memory at all times, ready for the router to pick them. A model that activates 4 billion per token might have 30 billion, 120 billion, or more total parameters.

Do the arithmetic. A 30 billion parameter model in 16-bit precision is 60 gigabytes of weights before anything else. Even squeezed to a 4-bit quantization that's still around 15 or 16 gigabytes. A 4 gigabyte card can't hold the weights alone, so it's not even a question of how much context length you need or how much headroom you want.

And weights aren't the whole memory bill either. There's the key-value cache, which grows with sequence length, plus intermediate activations and general overhead, so the real requirement sits above the bare weight size.

So the right way to say it is: the small active parameter count is why an MoE model is fast and cheap to *compute* per token, but the *memory* you need is set by the total parameter count, and for any realistic MoE with 4 billion active experts that total is far beyond what 4 gigabytes can hold. You'd typically need at least around 16 gigabytes with aggressive quantization, and considerably more otherwise.
