# Exchange 1

USER: Why can a 16 GB GPU sometimes run an MoE model with 30 billion total parameters, but not necessarily a 30 billion parameter dense model? Explain the difference between active parameters and the memory required to store the model.

ASSISTANT: The key is that those two numbers measure different things: how much of the model must sit in memory at all times, versus how much of it actually does work on each token.

A dense 30 billion parameter model has no shortcuts. Every single one of its 30 billion weights participates in computing every output token. So to run it, you need all 30 billion parameters resident in GPU memory simultaneously. At 16-bit precision that's roughly 60 gigabytes just for the weights, far beyond a 16 gigabyte card. Even at 4-bit quantization you're looking at around 15 to 17 gigabytes for the weights alone, which leaves almost no room for the KV cache, activations, and the rest of the runtime overhead that a real inference session needs. It simply doesn't fit with headroom, so in practice it's not reliably runnable on 16 gigabytes.

A mixture-of-experts model is structured very differently. Its total parameter count might be 30 billion, but most of those parameters live inside a bank of "expert" sub-networks that are mostly idle. For each token, a router picks only a small subset of experts to activate, often just a handful out of many. So the "active parameters" per token might be only 2 or 3 billion, even though the model stores all 30 billion. That distinction is what makes it runnable on smaller hardware in two related ways. First, the compute and memory bandwidth per token scale with the active count, not the total, so generation is fast enough on modest hardware. Second, and more importantly for your question, quantization strategies can be applied aggressively to expert models because each individual expert is small and rarely all needed at once; a 4-bit or even lower-precision MoE can have its full weight set compressed enough to land within 16 gigabytes while still keeping the active computation cheap.

So the memory requirement is governed by total parameters, which must be stored, but the practical runnability on a small GPU is driven by how much of that you can compress and how little work each token demands. A dense model forces you to store and use all 30 billion at full fidelity for every token, while an MoE lets you store 30 billion in a heavily compressed form and only ever touch a fraction of them per token. That's why the same headline parameter count can fit on a 16 gigabyte card as an MoE but not as a dense model.

One caveat worth stating plainly: this is a general explanation, and whether a specific 30 billion MoE actually fits in 16 gigabytes depends on its exact architecture, how many experts it activates, and the quantization level used, so I'd treat "sometimes" in your question as doing real work there.
