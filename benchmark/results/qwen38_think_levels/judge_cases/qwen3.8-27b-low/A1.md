Both models must hold all weights in memory, so the total parameter count sets the memory need for both; a 30B model at 4-bit needs roughly 15 to 18 GB either way and may not fit 16 GB. An MoE activates only a few experts per token, so it is faster and needs less compute, not less memory. A correct answer separates speed and compute (active parameters) from storage (total parameters) and does not claim MoE needs less VRAM by nature.

USER: Why can a 16 GB GPU sometimes run an MoE model with 30 billion total parameters, but not necessarily a 30 billion parameter dense model? Explain the difference between active parameters and the memory required to store the model.

ASSISTANT: Great question, and it gets at a subtle but important distinction.

So here's the key idea. When people say a model has thirty billion parameters, they mean thirty billion weights stored on disk or in memory. But "parameters" and "compute" are not the same thing. In a dense model, every single one of those thirty billion weights participates in computing the output for every token. You feed a word in, it flows through the attention layers and the feed-forward layers, and the entire network lights up. That's the definition of dense.

A mixture-of-experts model takes a different approach, mostly in the feed-forward layers. Instead of one big feed-forward block per layer, you have many smaller "expert" blocks, and a lightweight router decides, for each token, which few experts to send it through. So if you have a model with thirty billion total parameters but the router picks only two out of eight experts, maybe only about five or six billion parameters actually do any computation for that token. Those are the "active" parameters. The rest sit there, idle, waiting to be picked for some other token.

Now here's where the memory question gets interesting, because there are two separate things eating your GPU's memory. The first is the weights themselves. And this is the part that surprises people: you still have to store all thirty billion weights, even the ones that aren't active. The router can send any token to any expert, so you can't just load a few experts and hope for the best. All thirty billion weights have to be resident in memory. So in that sense, the weight storage cost is the same whether the model is dense or MoE.

The second thing eating memory is what's called activation memory. When you're actually computing a forward pass, the intermediate results the network produces also take up memory. In a dense thirty-billion model, every layer's full feed-forward block is computing simultaneously, and those intermediate tensors can be quite large. In an MoE model, you're only computing through two or three small experts instead of one big block, so those intermediate tensors are much smaller. The peak activation memory during inference is noticeably lower.
