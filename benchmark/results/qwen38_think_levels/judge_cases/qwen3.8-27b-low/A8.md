# Exchange 1

USER: For a personal AI assistant, compare these two designs: one large LLM handles every request, versus a smaller router that sends simple commands to deterministic tools and only uses a larger LLM for complex questions. Which would you recommend and why?

ASSISTANT: I'd recommend the router design, with one important framing: treat the router as a shortcut in front of the LLM, not a gatekeeper that replaces it.

Here's the reasoning. A personal assistant is spoken to, and most of what people say to one is repetitive: "turn on the lights," "set a timer for ten minutes," "what's on my calendar tomorrow." Those are structured commands where you want an exact, fast, cheap answer. Pushing them through a large model every time means paying a full inference call — a second or two of latency, real money per request, and a small chance the model fumbles something that should be deterministic. You don't want an LLM guessing whether the volume should be forty or forty-one.

So a small, fast front end — a tiny classifier model, or even a short list of high-confidence patterns — catches those and hands them to a tool directly. That path is in milliseconds, costs nothing in inference, and is exact.

But the key design choice is what happens when the request doesn't fit neatly. You want it to fall through to the full LLM, which can also call tools via function calling. That handles the cases that look simple but aren't: "turn off the light in the bedroom but leave the kitchen one on because I'm coming home late." A rigid router would misroute that; an LLM gets it.

A few practical notes. The classifier itself should not be a hand-written rules list — that rots the moment you add a third tool. A small language model or an embedding-based matcher generalizes better and absorbs new tools with less effort. And keep the LLM path as the default, not the exception: if your router is wrong, the cost is one extra inference, not a failed command. That's a much safer failure mode.

The single-LLM design is fine to start with — it's the simplest thing to build and has no routing bugs by construction. But as the tool set grows and you care about latency and cost, the router layer is worth adding. It's really a performance and reliability layer, not a different philosophy.
