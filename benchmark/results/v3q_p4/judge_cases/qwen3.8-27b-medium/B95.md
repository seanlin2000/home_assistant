ASSISTANT: Here's how I'd think about it, given what the current hardware market looks like.

The core idea is a two-box split. A tiny always-on edge device handles the microphone, listens for a wake word like "Hey Jarvis," and streams only the captured audio clip to the main box. That's where the real work happens: speech-to-text, the language model, tool use, and text-to-speech sent back. Keeping the heavy lifting off the always-on box means low power draw and a clean privacy boundary, since the mic never records anything except after a wake word.

For components, at today's prices: a Raspberry Pi 5 with 8 or 16 gigabytes, running the wake word detector and piping audio to the main box, is the edge node, and it's roughly a hundred dollars, maybe a bit more for the 16-gig version after the recent memory price increases. The main box can be an Intel N100 mini PC, around two hundred dollars, plus a secondhand RTX 3060 with 12 gigabytes of video memory at roughly two and a half hundred dollars used, or an Intel Arc B580 for similar money. Add a decent USB conference microphone, fifty dollars, and you're at around six hundred, leaving a healthy cushion for a second mic in another room, a power supply, or saving up for a bigger GPU later.

The software stack is mostly open source. Whisper for speech-to-text, Ollama or llama.cpp running a 7B or 13B model, Piper for text-to-speech, Home Assistant as the smart home brain, and a local search engine like SearXNG feeding results back into the model for web questions. Home Assistant is the key integration point, because it already speaks to virtually every smart home device and has built-in hooks for exactly this kind of voice pipeline.

Now the honest limitations, and these matter more than the hardware. First, a 7B or 13B model is genuinely weaker than the cloud assistants you're replacing. It'll handle commands and simple questions fine, but multi-step reasoning, nuanced conversation, and following complex instructions will be noticeably clunkier. Second, latency: even with a GPU, you're looking at a few seconds from the end of your question to the start of the answer, versus under a second with a cloud service. It feels like a different product. Third, local web search is a weak link, because SearXNG returns page text that a small model can struggle to synthesize into a good answer. Fourth, natural conversation at length is hard, because small models lose the thread, and keeping long context in 12 gigs of memory is a real constraint.

On build order, I'd prioritize in three phases. Phase one: get the voice loop to smart home working end to end. Wake word, Whisper, a small local model, Home Assistant, Piper. You'll have a private "turn on the lights, what's the thermostat set to" assistant, which is the part that works reliably and gives you daily value while you improve the rest. Phase two: add web search and better context, and upgrade the model as budget allows. Phase three: conversation quality, multi-room mics, and polish. The through-line is: don't chase the conversational magic first, because that's the weakest link and the least certain payoff. Make the plumbing boring and reliable, and grow the intelligence as you can afford bigger video memory, which is honestly where most of your money buys the most capability.

One assumption to flag: these GPU and Pi prices are from current listings and can swing, especially with the memory shortage pushing things up this year, so I'd treat the six-hundred-dollar baseline as a rough figure and price the used GPU when you actually buy it.
