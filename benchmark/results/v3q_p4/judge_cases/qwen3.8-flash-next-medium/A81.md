The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. Websites the assistant then fetches see the IP address and the requests. What stays local: the audio and transcription if speech is processed locally, the full conversation and history, the model's reasoning and answers, and anything never put into a query. Minimizing exposure: keep personal details out of queries (write queries from the question, not the whole conversation), search only when needed, cache results, use a privacy-focused provider or a self-hosted metasearch proxy such as SearXNG, route through a VPN for IP privacy, and check the provider's data-retention terms.

The first architectural decision in any IP enrichment pipeline is whether to call an API or query a local database. Both work. The right choice depends on your volume, latency requirements, and operational constraints.

URL: https://dreaming.press/posts/2026-06-21-tavily-vs-exa-vs-linkup-web-search.html
Give an agent a search box and you've made a quiet architectural decision you probably didn't notice. "Search the web" sounds like one capability, but the APIs that provide it deliver the web at wildly different stages of doneness — and the stage you pick determines how much code you write, how many tokens you burn, and what you pay per query. The vendors don't really compete on finding better pages. They compete on how much of the reading they do before they hand it back.
## Rung one: raw links, you do the rest#
The bottom rung is the classic SERP API — Serper wrapping Google's results, or the Brave Search API serving its own independent index. You send a query, you get back links and snippets: titles, URLs, a sentence of context. That's it. Whatever the agent actually needs to read lives behind those links, which means you still have to fetch each page, strip the nav and cookie banners, and feed the cleaned text to your model yourself.
## Rung two: cleaned content, ready to read#
That this rung is now considered strategic infrastructure isn't speculation. In February 2026, Nebius — a public AI-cloud company — announced it was acquiring Tavily to add "agentic search" to its platform, a deal reported around $275M. When a cloud provider buys a search API the way it would buy a database, the signal is clear: feeding the web to agents has graduated from a developer convenience to a layer of the stack worth owning.
## Buy the rung, not the brand#
- You want the answer, not the evidence → Linkup or Perplexity Sonar. Least code, highest per-query cost, least visibility into how the answer was built.

ASSISTANT: Short version: your model and your conversation stay home, but the query string is a leak, and it is the leak people actually get caught by.

What stays local. The model weights, your prompts, chat history, any documents you feed it, its reasoning, and the answer it writes are never seen by the search provider. Nothing about your conversation is sent unless you or the agent puts it into a search request.

What does leave your machine. First and most important, the query text. In an agentic setup the model usually writes or rewrites the query itself, so it is the model's paraphrase of your question that gets transmitted. That is fine for "what year was the Cornell lab built" and dangerous for a request whose phrasing contains a client name, an internal project code, an email address, an account number, a file path, or a sentence copied from a document you pasted in. Second, your API key, which ties every query to your billing account, so the provider knows all those queries came from one identified customer even when it doesn't know which human typed them. Third, network metadata: your IP address, the timestamp, and request headers such as the user agent, which Brave's own privacy notice lists as the personal data it processes for billing and abuse prevention. Fourth, if the API returns plain links rather than finished content, your agent then fetches those pages itself, so the publishers see your IP and user agent too, which is a second exposure the search provider never mentions. Fifth, some APIs offer extract, summarize or answer endpoints, and using those means sending URLs and often page text to them as well.

Two things worth knowing about who actually receives the query. Brave, Exa and Tavily run their own indexes, and their stated handling is fairly clean: Brave keeps search query logs for up to 90 days on standard plans and says it has no way to link a query to an individual, with a Zero Data Retention option sold on its enterprise tier; Exa's zero data retention is enterprise only, and Tavily's is available on request. Serper, SerpApi and many cheaper "SERP" APIs are wrappers that forward your query in real time to Google or Bing, which log it under their own consumer policies and ad profiling. That forwarding is invisible to you and you have no deletion recourse, so if privacy matters, the wrapper versus independent index distinction matters more than price. Also, even with zero data retention, a query in flight is still obtainable by a valid warrant, since Brave's own retention language carves out its legal obligations.

To minimize exposure, treat the query as untrusted output and scrub it. Have the model draft a generic keyword query, run a redaction pass over it locally for names, emails, numbers and proprietary terms, and only then make the HTTP call. Never let the model interpolate raw user text or document excerpts into a query parameter. Keep the API key in an environment variable outside the model's context window, on a separate low-limit account you can revoke, so prompt injection in a retrieved page can't read the key or use your search quota as an exfiltration channel. Cap results per call and allow a small set of hosts for the fetching step, and run the agent in a container or VM whose only permitted outbound destination is that one API host. Prefer an independently indexed provider, and ask for their DPA and zero data retention terms before committing. A proxy you control can strip headers and centralize the key, though your IP is still visible to the provider and routing through a VPN can trip their abuse detection.

One honest caveat: if anything in the pipeline is hosted, the exposure stops being small. Hosted embedding models for retrieval, or a cloud model used for reranking or drafting, send your text to a provider that logs prompts, and typical API log retention runs from a week to a month. A local model with a clean search query is a genuinely tight setup; a local model with a hosted embedder mostly isn't.
