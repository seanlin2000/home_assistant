Quantizing stores each weight in fewer bits than the usual 16. Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). Wrong memory figures are an error.

ASSISTANT: Quantizing a model means replacing its weights, which are stored as 16-bit floating-point numbers, with numbers that take far fewer bits, by grouping the weights into small blocks and storing, for each block, a low-bit integer index plus a scale and offset that let the original value be approximately reconstructed. A 4-bit weight can take one of sixteen levels within its block; a 2-bit weight only four. The idea is that relative precision matters more than absolute precision, so each block gets its own scale.

For the memory math, a 70-billion-parameter model at 16-bit precision needs 140 gigabytes just for the weights. At a nominal 4 bits per weight that is 35 gigabytes, and at a nominal 2 bits it is 17.5 gigabytes. In practice, though, real quantized files use slightly more than the headline number. Formats like GGUF's Q4_K_M average around 4.5 to 4.9 bits per weight because they keep the most sensitive layers at higher precision, and they must also store the per-block scales. A 70B model in Q4_K_M comes out around 38 to 43 gigabytes on disk, roughly 42.5 for Llama 3.3 70B, and you should budget a few gigabytes more at runtime for the key-value cache and other overhead, so about 45 gigabytes of memory to run it. Two-bit quants land nearer 20 gigabytes than 17.5 for the same reason.

The trade-offs are where it gets interesting. The gain is purely about fitting the model into memory and moving it faster: generation is bottlenecked by memory bandwidth more than by compute, so a 4-bit 70B model runs noticeably faster than a 16-bit one, and a 4-bit 70B model often beats a full-precision 8B model in quality while using similar memory.

What you pay for is accuracy per weight, and the damage is unevenly distributed. Around 4 bits is widely considered the sweet spot, commonly described as retaining roughly 98 percent of benchmark quality, with Q4, Q5 and Q6 effectively indistinguishable from each other to human evaluators on writing, summarization and question answering. Loss becomes perceptible at 3 bits and steep at 2. Quantization degrades non-linearly: perplexity rises, instruction-following gets sloppier, and hallucination rates climb, because a 2-bit grid has only four levels per block and cannot represent fine differences between weights. The failures show up first in tasks that depend on subtle distinctions, like exact arithmetic, long-range reasoning, code correctness, and following precise formatting instructions, and in long contexts, where the errors accumulate across layers.

Two additional caveats worth knowing. Quantizing weights is not the same as quantizing activations or the key-value cache; those are separate decisions with their own quality costs, and a quantized model can still need a full-precision cache. And quantization does not help prompt-heavy workloads proportionally, because the key-value cache grows with context length and is usually kept at higher precision, so a 70B model at 2 bits with a very long context can end up surprisingly close to its 4-bit footprint.
