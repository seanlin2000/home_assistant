Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

Why GPUs work so well

A neural net layer is a multiply-accumulate loop repeated billions of times: take a matrix of weights, multiply it by a vector or batch of activations, add, pass through a nonlinearity. That's embarrassingly parallel — every output element can be computed independently, with no branching and no dependencies between them. A CPU has a handful of wide, cleverly speculative cores optimized for finding parallelism in messy serial code. A GPU throws that away in favor of thousands of narrow cores plus dedicated matrix units — NVIDIA's Tensor Cores — which do small tiled matrix multiplies directly in hardware. On the current flagship, the B200, sources report roughly 9,000 TFLOPS of FP4 tensor throughput across 592 tensor cores, on a dual-die chip with 208 billion transistors.

Three other things matter as much as core count:

Mixed precision. Inference doesn't need IEEE floating point. INT8, FP8, FP6 and FP4 give you half or a quarter the bytes per weight and faster multiply-accumulate, with acceptable accuracy loss. Blackwell added native FP4; most NPUs support INT4 through FP16 natively too.

Memory bandwidth, which is the real ceiling for language models. This is worth dwelling on because it explains the whole specialized-chip industry. Autoregressive decoding — generating one token at a time — requires streaming essentially the entire weight set out of memory to do a small matrix-vector multiply, roughly one byte of traffic per flop or so. An H100's tensor cores want about 300 flops per byte before they'd be the limiting factor, so decode runs something like 99 percent below the compute ceiling. The cores sit idle waiting on memory. That's why NVIDIA sells the H200 with more bandwidth rather than more flops, and why the B200 jumps to around 8 terabytes per second of HBM3e.

Software. CUDA, cuDNN, TensorRT-LLM, Triton, vLLM, a decade of kernels tuned per layer type. A new architecture has to be made to run your model before its spec sheet means anything.
