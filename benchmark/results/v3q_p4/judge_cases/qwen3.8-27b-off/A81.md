Here's the general picture for that setup, assuming a typical text-based search API like SerpApi, Tavily, or Brave Search:

**What stays local**

The model itself never leaves your machine. Your weights, your prompts as you type them, your conversation history, and any intermediate reasoning the model does before deciding to search — all of that is on your hardware. If you're using a framework like Ollama, LM Studio, or plain Python with llama.cpp, nothing about the model or your full chat context is transmitted unless *you* send it.

**What gets transmitted**

When the model decides it needs to search, it produces a short query — usually a handful of words or a sentence — and that query is sent to the search provider over HTTPS. The provider then returns snippets, titles, URLs, and sometimes full page content, which come back to your machine and get fed into the model as context.

So the search provider sees:
- Your IP address (or the IP of any proxy you route through)
- The exact search query string
- A timestamp for each request
- Possibly API key or account metadata that ties requests to your identity

They do *not* see your full conversation, your system prompt, your local files, or the model's weights. They only see what you explicitly send in the API call.

**How to minimize exposure**

A few practical steps, roughly in order of impact:

First, keep queries as short and de-identified as possible. You can instruct the model via your system prompt to strip names, addresses, or other sensitive details before forming a search query. That's the single biggest lever you have.

Second, route the API call through a local proxy or something like Tor if you want to decouple your IP from the requests. This adds latency but makes it harder for the provider to correlate searches with your network identity.

Third, use an ephemeral or disposable API key rather than one tied to your main account, so that even if the provider logs requests, they're not clearly linked to you personally.

Fourth, review the provider's data retention policy. Some search APIs log queries for a period and some claim not to store them long-term. If you can find that documented, it tells you how long the exposure window actually is.

Fifth, if your workflow allows it, consider whether you truly need a live web search or whether a local index of pages you've already downloaded would suffice for many queries. That eliminates the transmission entirely for those cases.
