The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. # Exchange 1

USER: If I run a language model locally on my computer but use an external web-search API, what information can the search provider see? Explain what stays local, what gets transmitted, and how I can minimize data exposure.

ASSISTANT: Good question — this is a common setup, and it's worth understanding exactly what crosses your network boundary.

**What stays local:** The model itself never leaves your machine. Your full conversation history, the prompts you've already sent to the model, any sensitive context you've loaded into the chat, and the model's raw reasoning all stay on your hardware. The search provider has no access to your model weights, your local files, or anything you've typed that wasn't specifically sent as a search query.

**What gets transmitted:** When the model decides to call the web-search API, it sends the search query — which is typically a short phrase or question derived from your prompt. That's the main thing the provider sees. Depending on how the API is set up, they may also see:

- Your IP address, unless you route through a proxy
- Any headers you send (API keys are for authentication and shouldn't contain personal data, but some people put metadata in custom headers)
- The search results that come back, which the model then uses to form its answer — so the provider logs what was returned

The key nuance: the search query is *derived* from your prompt. If you ask "summarize this medical document and find current treatment guidelines," the model might send something like "current treatment guidelines for [condition]" as the search query. That's a distilled version, but it can still reveal what topic you're working on.

**How to minimize exposure:**

1. **Use a privacy-focused search API.** Providers like SearXNG (self-hosted), DuckDuckGo's API, or Tavily have different logging policies. Read their data retention and privacy pages specifically — "we don't sell your data" is not the same as "we don't log queries."

2. **Route through a proxy or VPN** so your IP address isn't directly tied to your searches. This is especially important if you're doing sensitive research.

3. **Be deliberate about what you ask in one prompt.** If you're working on something sensitive, consider splitting your workflow: do the local reasoning with the model first, then issue a narrowly scoped search query that doesn't include unnecessary context. You can even pre-write the search term yourself and paste it in, rather than letting the model generate it from your full conversation.

4. **Check the tool-calling configuration.** In frameworks like LangChain, LlamaIndex, or Ollama with plugins, you can often configure exactly what gets sent to the search tool. Some let you restrict the query to a fixed template or add a "no context" flag so only your explicit search term goes out, not surrounding chat history.
