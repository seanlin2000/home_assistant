Reference sketch (what a correct answer must contain):
Quantizing stores each weight in fewer bits than the usual 16. Weights alone: 16-bit about 140 GB; 4-bit 70 billion times half a byte, about 35 GB (real 4-bit files run roughly 38 to 42 GB because of scales and mixed precision); 2-bit about 17.5 GB (about 20 to 25 GB in practice). The context cache and activations come on top. Trade-offs: some loss of quality, small at 4-bit and marked at 2-bit (reasoning and factual accuracy suffer most); faster generation, because inference is limited by memory bandwidth; careful methods (GPTQ, AWQ, importance-weighted quantization) reduce the loss. Wrong memory figures are an error.

ASSISTANT: Quantizing means storing each of the model's seventy billion weights using fewer bits, so instead of sixteen bits per weight you use four or two, and you map the original values onto a much smaller set of levels. For memory, seventy billion weights at four bits is about thirty-five gigabytes, and at two bits it is about seventeen and a half gigabytes. Those are weights only, and real files run somewhat larger because some layers stay at higher precision and you also need memory for the context cache. For comparison, the sixteen-bit version would be around one hundred forty gigabytes. The trade-offs are these. Fewer bits means smaller memory, and often faster generation, because less data has to be read per token. But you lose precision, so quality drops. Four-bit usually costs only a small loss with good methods. Two-bit is much riskier: expect noticeably worse reasoning, coding and factual accuracy, and sometimes broken output. Large models tolerate it better than small ones. So four-bit is the practical sweet spot, and two-bit is for when memory is the hard limit.
