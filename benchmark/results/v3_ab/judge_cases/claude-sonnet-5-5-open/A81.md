Reference sketch (what a correct answer must contain):
The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. Websites the assistant then fetches see the IP address and the requests. What stays local: the audio and transcription if speech is processed locally, the full conversation and history, the model's reasoning and answers, and anything never put into a query. Minimizing exposure: keep personal details out of queries (write queries from the question, not the whole conversation), search only when needed, cache results, use a privacy-focused provider or a self-hosted metasearch proxy such as SearXNG, route through a VPN for IP privacy, and check the provider's data-retention terms.

# Exchange 1

USER: If I run a language model locally on my computer but use an external web-search API, what information can the search provider see? Explain what stays local, what gets transmitted, and how I can minimize data exposure.

ASSISTANT: If the model runs locally, your prompts, conversation history, files and the model's reasoning all stay on your machine. What leaves is only the search query that your software sends to the search provider, plus the metadata that comes with any web request: your IP address, timestamps, headers like the user agent, and the API key that ties queries to your account. The provider can see every query text, when you sent it, and can link them into a profile over time. If the model writes the queries, they may contain details from your conversation, so personal information can leak inside them. Pages you then fetch are visible to those sites as well. To minimize exposure, first make the software send short, generic keyword queries and strip names, addresses and other personal details before searching. Second, use a provider with a clear no-logging policy, or a self-hosted meta-search engine such as SearXNG, which also mixes your traffic with other users. Third, route requests through a VPN or proxy to hide your IP address. Fourth, avoid putting secrets or private documents into anything that triggers a search.
