Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

ASSISTANT: Great question, and it's a genuinely good one to understand because it's reshaping the whole AI hardware market.

Let's start with why GPUs are so good at AI inference. A neural network doing inference is really just a giant wall of math: multiplying and adding vectors of numbers, over and over, in a very regular pattern. A CPU has maybe a dozen or two dozen cores built for juggling all sorts of different tasks. A GPU has tens of thousands of small, simple cores, which is a terrible design for a spreadsheet and a magnificent design for that kind of mass, repetitive math. Two things make this especially true for inference: the number of parallel arithmetic units, and the memory bandwidth, meaning how fast data can flow in from memory. Inference on a big language model is often "memory bound," so the chip spends more time waiting on weights to arrive from memory than actually computing. NVIDIA GPUs have very wide memory buses, and they've spent a decade adding tensor cores, specialized circuit blocks that do matrix multiplication at high precision, including low-precision formats like FP8 that inference loves. On top of that, there's the ecosystem moat: CUDA, TensorRT-LLM, the optimized runtimes. Most people can't match NVIDIA's raw speed without also having to rebuild their software stack, and that's a huge practical cost.

Now the three categories. A GPU, as we said, is a general-purpose parallel processor. It can train models, run inference, render video, and do scientific computing. That flexibility is its superpower and also its weakness: it's carrying machinery and flexibility that a pure inference chip doesn't need.

An ASIC, application-specific integrated circuit, is a chip designed for one job. Google's TPUs are the classic example. They're built around matrix multiplication and a fixed data path, which lets them do more useful math per watt than a GPU. You trade away generality for efficiency. Amazon's Trainium and Inferentia and Microsoft's Maia chips fit in this category too.

Specialized inference processors are a newer, more extreme version of that idea, and this is where it gets interesting. Companies like Groq and Cerebras made a specific bet: they figured out that for LLM inference, the bottleneck is memory bandwidth, so what if you put the memory on the chip itself? Groq's LPU uses on-chip SRAM with a compiler that schedules every operation deterministically, so nothing ever has to wait for memory. Cerebras literally uses a wafer-scale chip with tens of gigabytes of on-chip SRAM and memory bandwidth measured in petabytes per second, compared to maybe a few terabytes on an H100. The result is that for a fixed model they can produce tokens dramatically faster than a GPU can. Groq's own figures show hundreds of tokens per second versus tens of tokens per second on comparable GPU setups, and independent benchmarks tend to come in somewhere in between vendor claims, the gap being a few to twenty percent depending on how mature the software is. A fun footnote from this year: NVIDIA licensed Groq's technology and built an LPU-based product of its own, so the line between these categories is literally blurring.

So when would a specialized chip outperform an NVIDIA GPU? A few circumstances. First, if you're serving one or a few fixed models at scale and per-token cost is everything: the specialized silicon does the same job at lower power, and cloud providers price that into the tokens. AWS, for example, advertises its Inferentia chips as dramatically cheaper than H100s for in-AWS workloads. Second, if you're latency-sensitive, like a voice assistant or a real-time application where token speed directly determines user experience. Third, if you're power-constrained, because the specialized designs typically win on tokens per watt.

The flip side is when the GPU still wins, and it's a big list. If your models change often, if you need to train as well as serve, if you need a mature software ecosystem and the ability to migrate between architectures, or if your utilization is high enough that you can amortize the expensive hardware. That's the pattern the industry is converging on: specialized silicon takes the high-throughput, latency-sensitive, single-workload tier, GPUs hold the flexible middle, and by around 2027 expect hybrid setups to become normal, where one pipeline uses different chips for different phases.

One honest caveat: vendor benchmarks in this space are consistently flatter than independent tests, so take specific token-per-second numbers with that grain of salt.
