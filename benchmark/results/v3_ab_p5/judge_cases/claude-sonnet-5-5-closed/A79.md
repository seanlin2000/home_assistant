Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

# Exchange 1

USER: Why are GPUs so effective at AI inference? Explain the differences between GPUs, ASICs, and specialized inference processors. Under what circumstances could a specialized chip outperform an NVIDIA GPU?

ASSISTANT: GPUs are good at inference because running a neural network is mostly huge amounts of matrix multiplication, and a GPU has thousands of small cores that do those multiplications in parallel. They also have very fast memory, which matters because generating text is usually limited by how quickly you can read the model's weights, not by raw arithmetic. A mature software ecosystem, CUDA for NVIDIA, is a big part of the appeal. An ASIC is a chip designed for one job. Google's TPU is the well-known example. It drops general-purpose flexibility and spends its silicon on exactly the operations a model needs, so it can be more efficient. Specialized inference processors go further, for example designs that keep the whole model in on-chip memory, like Groq and Cerebras, or chips built only for transformers. A specialized chip can beat an NVIDIA GPU when the workload is stable and large enough to justify the design, when latency matters more than flexibility, when energy per token is the main cost, or when memory bandwidth is the bottleneck and the chip attacks that directly. The trade-off is less flexibility and weaker software support.
