Reference sketch (what a correct answer must contain):
The search provider sees each query the model writes (which can carry personal details from the conversation), the IP address it came from, the API key and so the account and billing identity behind it, timing and frequency, and request metadata such as the user agent. Websites the assistant then fetches see the IP address and the requests. What stays local: the audio and transcription if speech is processed locally, the full conversation and history, the model's reasoning and answers, and anything never put into a query. Minimizing exposure: keep personal details out of queries (write queries from the question, not the whole conversation), search only when needed, cache results, use a privacy-focused provider or a self-hosted metasearch proxy such as SearXNG, route through a VPN for IP privacy, and check the provider's data-retention terms.

# Exchange 1

USER: If I run a language model locally on my computer but use an external web-search API, what information can the search provider see? Explain what stays local, what gets transmitted, and how I can minimize data exposure.

ASSISTANT: If the model runs locally, your prompts, conversation history, files and the model's reasoning all stay on your machine. What leaves is only the search query that your software sends to the search API, plus the usual network metadata. The provider can see the query text, your IP address, the time, your API key or account, and headers such as your user agent. If your tool builds queries from the conversation, those queries can reveal personal details, because the model may paste in names, places or context. The provider generally cannot see your full chat or the model's answer, unless you send them. If you also fetch the result pages, the sites you visit see your IP address too. To minimize exposure, first tell the model to keep queries short and generic, with no names, addresses or private details. Second, review or filter outgoing queries in your tool layer. Third, use a privacy-focused search provider with a no-logging policy, or run your own search instance. Fourth, route traffic through a VPN, and use a dedicated API key not tied to your identity. Finally, check the provider's retention policy.
