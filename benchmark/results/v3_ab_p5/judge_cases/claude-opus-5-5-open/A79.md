Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

# Exchange 1

USER: Why are GPUs so effective at AI inference? Explain the differences between GPUs, ASICs, and specialized inference processors. Under what circumstances could a specialized chip outperform an NVIDIA GPU?

ASSISTANT: GPUs are good at inference because running a neural network is mostly huge matrix multiplications, and a GPU has thousands of small cores that do them in parallel, very fast memory to feed them, and a mature software stack, CUDA, that every framework already targets. The difference between the chip types is flexibility versus specialization. A GPU can train and serve any model, which is why NVIDIA dominates. An ASIC is a chip built for one job; Google's TPU is the classic example. Specialized inference processors, like Groq's chips, Cerebras's wafer-scale engine, or transformer-only designs, go further, often keeping weights in on-chip memory or hard-wiring the transformer pattern, because generating text is usually limited by how fast weights move from memory, not by raw math. A specialized chip can beat an NVIDIA GPU when the workload is huge and stable, like serving one popular model at scale, when per-user latency matters most, or when power and cost per token dominate. It loses when models change quickly or you need training, because the GPU's software ecosystem and versatility win.
