USER: What does it mean to quantize a 70-billion-parameter language model to 4-bit or 2-bit precision? How much memory would the weights require in each case, and what trade-offs does quantization introduce?

ASSISTANT: Quantizing a model means shrinking the numbers that make up its weights so they take less room. A standard 70-billion-parameter model stores each weight as a 16-bit floating-point number, which is two bytes per weight. So the weights alone come to about 140 gigabytes, before you count anything else.

At 4-bit precision, each weight takes half a byte, so 70 billion of them work out to roughly 35 gigabytes — small enough to fit on a single 48-gigabyte GPU or a Mac with enough unified memory. At 2-bit precision it's a quarter of a byte per weight, about 17.5 gigabytes, which fits comfortably on a 24-gigabyte consumer card. The usual rule of thumb is eight bits per parameter per byte level, so one byte per parameter gives you 70 gigabytes and four bits gives you half that.

A few things to keep straight. That figure covers the weights only. When you actually run the model you also need memory for the key-value cache that holds the context as you generate text, plus activations and some overhead, so a 35-gigabyte weight file usually wants more than 35 gigabytes of headroom in practice, especially at long context lengths. Quantization also does not make the model faster in the sense of doing fewer calculations; it reduces memory bandwidth pressure, which is what speeds up token generation on most hardware.

The trade-offs are quality and fragility. Dropping from 16 bits to 4 is generally close to painless for a model this size — you lose a little accuracy on hard reasoning, exact math, long-context retrieval, and tool-calling reliability, but most everyday use feels nearly identical. Two-bit is a different story. At that level the weight matrices no longer hold enough information, and quality drops noticeably; perplexity rises, and the model gets worse at following instructions and multi-step reasoning. Modern schemes like GPTQ, AWQ, QuIP# and MXFP4 try to soften the blow by keeping some layers or some values at higher precision, using group-wise scaling factors so each small block of weights has its own multiplier, and preserving a few outlier weights in higher precision. Those tricks make 2-bit survivable where it once was unusable, but they add complexity: extra bits from the scale factors mean an effective weight size slightly above the nominal bit count, and some layers like attention output projections are often left at 4 or 8 bits because quantizing them hurts disproportionately.
