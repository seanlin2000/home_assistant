Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

ASSISTANT: Let me start with why GPUs are so good at inference in the first place. Modern AI models, especially large language models, are fundamentally one thing: enormous matrix multiplications. A single forward pass through a transformer means multiplying huge matrices of weights by vectors of data, over and over. That workload has three properties that match GPU design almost perfectly. First, it's massively parallel — thousands of independent floating point operations can happen at the same time, which is exactly what a GPU's tens of thousands of small cores are built for. Second, inference is often memory-bandwidth bound rather than compute bound, meaning the bottleneck is getting weights from memory into the math units, and GPUs ship with high-bandwidth memory, or HBM, that moves terabytes of data per second. Third, and this is the underrated one, there's the ecosystem: CUDA, tensor cores tuned specifically for low-precision arithmetic, and a mature software stack. A big share of the "GPU advantage" in the real world is that everything just works on them.

Now the three categories. A GPU is a general-purpose parallel processor. It has lots of cores, but it also has a lot of generality: branch logic, flexible memory addressing, a wide instruction set. That generality is what lets you run training, inference, rendering, and everything in between on the same silicon.

An ASIC, application-specific integrated circuit, is the opposite end of the spectrum: silicon designed for one narrow job. The classic AI examples are Google's TPUs and AWS's Trainium and Inferentia chips. These are less flexible than GPUs, but because the hardware only has to do one thing well, it can be faster and far more power-efficient per operation for that workload. TPUs, for instance, claim roughly 30 percent lower inference cost than NVIDIA's H100 for LLM workloads, and Inferentia claims even steeper cost reductions within AWS.

Specialized inference processors go further still. They make dramatic physical bets specifically for serving models. Cerebras builds a wafer-scale engine — essentially an entire silicon wafer as one chip — with 44 gigabytes of on-chip memory, so a large model can live entirely on the chip itself and never pay the cost of shuttling data off-chip. Groq takes the other path: a Language Processing Unit with compiler-managed on-chip memory and fully deterministic execution, so every step of the computation is scheduled in advance with no waiting or stalling. Both companies claim inference rates far above GPUs on comparable models — Cerebras claims up to 3,000 tokens per second on some open models, with vendor claims of single-digit multiples over GPUs, though I'd flag that most of these are vendor-reported numbers, and NVIDIA's own response was telling: it licensed Groq's technology and shipped it in a hybrid product in 2026.

So when could a specialized chip beat an NVIDIA GPU? A few circumstances. One: latency-sensitive, high-throughput serving of a known, fixed model. If you're serving one or a handful of large models to millions of users and you care about tokens per second and cost per token, purpose-built silicon can win decisively, because it can hard-code the data path for exactly that workload. Two: when the model fits in on-chip memory. That's Cerebras's and Groq's core trick — by keeping weights on-chip instead of in HBM, they sidestep the memory wall that throttles GPUs. Three: power and cost at scale. For massive steady workloads, energy per token can matter more than peak speed, and specialized designs are usually more efficient per watt. Four: deterministic, predictable latency, which Groq-style architectures deliver by construction and GPUs can't guarantee as tightly.

The flip side is why GPUs still dominate: flexibility. If your model changes frequently, if you mix training and inference, if you use exotic model architectures or new techniques that need custom kernels, the general-purpose nature and software maturity of CUDA is a moat that specialized silicon struggles to cross. The industry consensus by 2026 seems to be that this won't end in a winner-take-all: specialized chips take the latency-critical, high-volume inference tier, GPUs hold the flexible middle, and hybrid pipelines — different chips handling different phases of the same request — are becoming the norm.
