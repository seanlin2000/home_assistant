# Exchange 1

USER: Imagine I want to build a private, locally hosted voice assistant that can answer general questions, search the web, control smart-home devices, and have natural conversations. I have a $1,000 hardware budget. Propose an architecture, explain the components, identify the biggest limitations, and prioritize what I should build first.

ASSISTANT: Here's how I'd approach it. One important framing point first: with a $1,000 budget, you should resist the urge to build two machines. A single compact workstation that does everything, plus a cheap microphone, beats splitting a voice node and a brain node when money is this tight. Separating them buys you some latency and isolation, but at this budget it usually means underbuying both halves.

The architecture, in one box:

A used mid-range desktop — think a 12th-gen Intel i5, 64 gigs of RAM, a 1-terabyte SSD — as the central computer, plus a used RTX 3060 with 12 gigs of video memory. That card is the sweet spot right now; roughly 260 dollars on the used market, and 12 gigs lets you run a 7-to-8-billion-parameter model at Q4 quantization with room left for context and tool calling. On top of that, a decent USB conference-style microphone with echo cancellation, about 60 dollars, a Bluetooth speaker for 30, and a Zigbee dongle around 30 dollars if you want to reach cheap sensors and bulbs. That puts you around 830, leaving buffer for price swings — all of these numbers are ballpark, so check current used-market pricing before you commit.

The software stack is almost entirely free, which is what makes the budget work. Home Assistant is your home-control hub and, importantly, it has a built-in local voice pipeline: wake-word detection with openWakeWord or Porcupine, voice activity detection with Silero, speech-to-text with faster-whisper, and text-to-speech with Piper, all running locally. That single package gives you the whole voice loop, plus structured control of your devices. Then you run Ollama as the model server with a 7-to-8B instruct model that supports tool calling — Llama 3.1 8B, Qwen, or Gemma in that class — and hook it into Home Assistant as the conversational brain, so it can decide to answer, search, or issue a device command. For web search, run a SearXNG meta-search instance locally so queries never leave the house, and expose its results to the model as a tool.

Now the honest limitations, because they're real.
