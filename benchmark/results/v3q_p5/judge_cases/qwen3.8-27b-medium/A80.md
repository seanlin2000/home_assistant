ASSISTANT: Quantization means replacing the full-precision numbers that a model's weights are stored as with shorter, lower-precision numbers, so each weight takes fewer bits of memory. A model trained in standard precision stores each weight as a 16-bit or 32-bit floating point number. Quantizing to 4 bits stores each weight using just four bits, and 2 bits uses even fewer, typically with the weights grouped into small blocks that share a scale or offset so the small integer codes can be turned back into approximate real values when the model runs. It is a lossy compression: you throw away precision you judge the model can mostly afford to lose.

For the memory math, each parameter in a 70-billion-parameter model is seven-ti-billion parameters. In 16-bit precision that is roughly 140 gigabytes of just weights; in 32-bit, about 280. At 4 bits you divide by four, landing around 17.5 gigabytes for the weights alone. At 2 bits you divide by eight, around 8.75 gigabytes. Those are the weights in isolation; a real system also needs memory for the activations during generation and the KV cache as context grows, so the true footprint is somewhat higher, but the weight figures give the order of magnitude, and they are exactly why quantization lets a 70B model run on a workstation or a high-end laptop card that could never hold the full 140 gigabytes.

The trade-offs. First, quality: the model becomes a slightly less faithful copy of the original. At 4 bits the degradation is usually small for many tasks, though it can be noticeable in fine reasoning, code, and long-tail knowledge. At 2 bits the degradation is often substantial, with measurable drops in accuracy and more frequent incoherent outputs, so 2-bit is generally pushed to the edge of being usable and is mostly chosen when you are desperate for the last few gigabytes. Second, speed and cost: lower precision means less data moved between memory and the processor, which is usually the real bottleneck during generation, so inference gets faster and cheaper, and more requests can run in parallel. Third, practical considerations: you typically lose the ability to fine-tune the model in that low precision without extra techniques, some hardware is far better at certain bit widths than others, and the choice of method, like grouped or block-wise quantization with calibration, matters a lot for how much quality survives.

In short, 4-bit is a common, fairly safe middle ground that cuts memory and boosts throughput with modest quality cost, while 2-bit is an aggressive squeeze you pay for in accuracy.
