Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

ASSISTANT: Start with what inference actually is at the hardware level, because that explains everything else.

Almost all of the work in a modern model is the same handful of operations repeated: dense matrix multiplications, plus attention, plus a few elementwise things like activations and normalization. A matrix multiply is embarrassingly parallel — thousands of independent multiply-accumulate operations that don't depend on each other — and it tolerates low numerical precision, since neural nets are forgiving of rounding error. That combination is exactly what a GPU's silicon is shaped for. It has thousands of simple cores running in lockstep, and since roughly 2018 dedicated tensor cores that chew on small matrix tiles at FP16, BF16 and FP8 rather than doing general floating point. An H100, for example, is rated by NVIDIA at roughly two thousand teraflops of dense FP8 tensor work while burning about 700 watts.

The crucial nuance is that inference has two phases with different bottlenecks. Prefill, where the prompt is processed all at once, is compute-bound: many tokens, lots of matmuls, plenty of arithmetic per byte of weight read, so raw tensor throughput matters. Decode, where the model generates one token at a time, is memory-bound: to produce a single output token you must read essentially every weight in the model, so the limit is how fast you can stream weights from memory. On an H100 that streaming limit is HBM3 at about 3.35 terabytes per second. That single number is why people keep building chips that attack memory rather than flops.

Now the three families.

A GPU is a general-purpose parallel processor. Hardware schedulers, warp scheduling, deep cache hierarchy, SIMT execution, and above all a software stack. Its real moat is not the silicon; it is CUDA plus the ecosystem built on it — cuBLAS, FlashAttention, TensorRT-LLM, vLLM, PyTorch — which means any new model architecture gets a working implementation in days. The cost of that flexibility is scheduling overhead, cache misses, instruction fetch, and the fact that the datapath has to be reconfigured by software for every layer.

An ASIC is application-specific silicon: the datapath is drawn onto the die rather than scheduled by a general-purpose engine. Google's TPU is the classic case, built around systolic arrays where data flows through a grid of multipliers with very little control logic, plus a compiler-first software stack, XLA. AWS Trainium, Inferentia, Microsoft's Maia and Meta's MTIA are the same idea inside their own clouds — Trainium uses scratchpad memories managed largely by the compiler, and AWS has been pushing its Neuron Kernel Interface as the escape hatch when automatic compilation isn't good enough. The advantage is efficiency: no wasted control logic, higher flops per watt and often lower cost per token, because these companies buy in enormous volume and don't need to sell flexibility. The disadvantage is capacity for change: the design is locked years ahead of the models it will run, and the ecosystem is younger and narrower.

A specialized inference processor goes further and rejects the whole GPU premise. Groq's LPU, originally its Tensor Streaming Processor, is the purest version: no caches and no hardware scheduler at all, just a large deterministic datapath with about 230 megabytes of on-chip SRAM delivering something like 230 terabytes per second of bandwidth, and a compiler that schedules every operation statically, cycle by cycle, so there is no unpredictability. That's roughly seventy times the memory bandwidth of an H100, at the price of having 230 megabytes of fast memory instead of 80 gigabytes of slower memory. Cerebras goes the other way, wafer-scale integration: one enormous die with a huge amount of on-chip SRAM, which is why it reports over a thousand tokens per second on Llama 3.1 405B, a model most GPU clouds barely serve at all. SambaNova takes a reconfigurable dataflow approach. The theme they share is that serving a model in production is not the same economic problem as training one, so the chip should follow the workload.

So, when does a specialized chip actually beat an NVIDIA GPU?

When the workload is decode-dominated and latency-sensitive. Interactive agents, voice, real-time coding assistants, anything where tokens per second per user is the metric rather than tokens per dollar across a thousand concurrent requests. Groq has reported roughly 300 tokens per second on Llama 2 70B, an order of magnitude better than an H100 cluster on the same workload, and that gap comes straight from SRAM versus HBM bandwidth. At small batch sizes, where a GPU is sitting idle waiting on memory, the specialized part is doing useful work every cycle.

When you can accept the capacity constraints. On-chip SRAM is tiny, so a big model has to be sharded across many chips, which only works if the interconnect and the compiler are good enough. This is why these vendors shine on mid-size, dense, quantized models and struggle, or refuse, on the very largest ones — SambaNova notes that neither Groq nor Cerebras serves Llama 3.1 405B in its configuration.

When power is the binding constraint rather than floor space being free. NVIDIA's own marketing for its Groq-derived parts claims 35 times more inference throughput per megawatt than GPUs, with 150 terabytes per second of SRAM bandwidth per LPU. If you are constrained by a power budget, efficiency per watt becomes the ranking metric.

When the workload is stable and well understood. If you're running a handful of known architectures, in known precisions, at known sequence lengths, you can amortize the painful part: writing kernels for a different compiler. Groq uses its own TSP compiler, Cerebras uses CSoft, and neither runs your custom CUDA kernels or FlashAttention implementation for free. If your pipeline is exotic, that rewrite cost can eat the entire performance win.
