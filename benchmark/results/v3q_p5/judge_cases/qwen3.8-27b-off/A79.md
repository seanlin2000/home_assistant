Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

USER: Why are GPUs so effective at AI inference? Explain the differences between GPUs, ASICs, and specialized inference processors. Under what circumstances could a specialized chip outperform an NVIDIA GPU?

ASSISTANT: The short version is that GPUs were built to do thousands of simple math operations at once, which happens to be exactly what running an AI model requires. A neural network's forward pass is mostly the same operation repeated across millions of numbers: multiply a batch of weights by a batch of inputs and add them up. That's a massively parallel job with very little branching or decision-making between steps, so a chip that can fire off thousands of multiply-accumulate operations in lockstep will chew through it far faster than a CPU, which is optimized for doing a few complex things sequentially.

GPUs also have other properties that help. They're memory-bandwidth hungry, and modern GPUs like the H100 or B200 have huge amounts of fast on-chip memory (HBM) plus very wide memory buses, so they can stream in weights without stalling the math units. Their tensor cores are dedicated hardware for exactly the matrix multiplications AI uses, doing mixed-precision work at enormous throughput. And there's a massive software ecosystem — CUDA, cuDNN, TensorRT — that means you don't have to write low-level code to get good performance.

Now the differences between the three categories:

A GPU is a general-purpose parallel processor. It can do graphics, scientific computing, machine learning training, and inference. That flexibility is its strength and also its weakness — it has more control logic, more generality in its instruction set, and more power overhead than a chip designed for one job.

An ASIC, or application-specific integrated circuit, is built to do one thing extremely well. Google's TPU is the classic example: it's essentially a giant array of matrix multipliers with very little else. It doesn't try to be general-purpose. For the specific workload it was designed around, it can hit better performance per watt and sometimes better raw throughput than a GPU, because every transistor is doing useful work rather than handling generality you don't need. The tradeoff is inflexibility: if your model architecture changes significantly or you want to run a different kind of workload, you're stuck with what the silicon does best.

Specialized inference processors sit somewhere in between and are often more about the memory problem than the math problem. Inference on large language models is frequently memory-bandwidth-bound rather than compute-bound: the bottleneck is moving hundreds of gigabytes of weights from high-bandwidth memory to the compute units, not the multiplication itself. Chips like Cerebras' wafer-scale engine, Groq's LPU, or various SRAM-heavy designs attack this by putting more memory on-chip or using different interconnects so that data movement isn't the bottleneck. They can get very low latency per token because they're optimized for exactly that streaming pattern.
