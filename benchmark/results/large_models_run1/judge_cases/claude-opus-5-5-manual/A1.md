Both models must hold all weights in memory, so the total parameter count sets the memory need for both; a 30B model at 4-bit needs roughly 15 to 18 GB either way and may not fit 16 GB. # Exchange 1

USER: Why can a 16 GB GPU sometimes run an MoE model with 30 billion total parameters, but not necessarily a 30 billion parameter dense model? Explain the difference between active parameters and the memory required to store the model.

ASSISTANT: Two different numbers are at play. The memory you need depends on every parameter the model has, because all of them have to be stored somewhere. The speed depends on how many parameters are read for each token. A dense 30 billion parameter model reads all 30 billion for every token, and at 4-bit that is roughly 15 to 17 gigabytes before you add the context cache, so on a 16 gigabyte card part of it spills into system RAM and every single token waits on that slow memory. A mixture-of-experts model with 30 billion total but only about 3 billion active still needs room for all 30 billion, but each token only touches a small slice. So you keep the shared layers and cache on the GPU and park the rarely used experts in system RAM, and because so little is read per token, it still runs at a usable speed. The MoE doesn't need less storage; it just tolerates having that storage somewhere slower.
