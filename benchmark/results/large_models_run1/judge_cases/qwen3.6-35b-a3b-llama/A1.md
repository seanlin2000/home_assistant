USER: Why can a 16 GB GPU sometimes run an MoE model with 30 billion total parameters, but not necessarily a 30 billion parameter dense model? Explain the difference between active parameters and the memory required to store the model.

ASSISTANT: The short answer is that a 16 GB GPU can often run a 30 billion parameter MoE model because it only needs to load the small fraction of parameters that are actually active for each token, whereas a dense model requires the entire 30 billion parameter weights to be loaded into memory simultaneously.

In a dense model, every single one of those 30 billion parameters must be stored in the GPU's VRAM so the model can access any of them. But an MoE model, or Mixture of Experts, splits those parameters into smaller groups called experts. When you send a piece of text to the model, it doesn't use all the experts. Instead, a gating mechanism decides which specific experts to use for that specific input. You might only use two or four out of the dozens of available experts for any given token.

This means the memory required is much lower because you are only loading the weights for the active experts. However, it is not just about the model weights. You also have to account for the optimizer states and the activations—the temporary data the model holds while it is processing the text. Even with MoE, if you are training the model, you still need to store gradients for all parameters, not just the active ones, which can quickly fill up that 16 GB. So, while MoE makes inference, or running the model, much more memory-efficient, it does not make training a 30 billion parameter model fit on a 16 GB GPU if you need to update all the weights.
