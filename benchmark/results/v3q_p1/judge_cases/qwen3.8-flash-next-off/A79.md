Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

Both Groq's LPU (Language Processing Unit) and Cerebras's WSE-3 (Wafer Scale Engine) solve the same bottleneck: the memory bandwidth wall that limits GPU inference.
During LLM token generation, the GPU must load the full model's weights from DRAM into compute cores for every forward pass. For a 70B parameter model, that means moving roughly 140GB of data on every token. GPU HBM bandwidth, at 3.35-4.8 TB/s on H100 and H200, limits how fast this can happen.
Groq's LPU uses on-chip SRAM that keeps model weights resident and eliminates the memory transfer step entirely. Cerebras's WSE-3 takes this further: a single wafer-scale chip with 900,000 cores and enough on-chip memory to store large models without external DRAM transfers. The result is TTFT under 100ms on Groq and 80-150ms on Cerebras, compared to 400-600ms typical on GPU inference.
GPU providers have closed part of this gap through speculative decoding, paged attention, KV-cache optimization, and TensorRT-LLM. On GMI Cloud, these optimizations narrow the speed difference enough that the practical gap for many workloads is significantly smaller than the raw benchmark numbers suggest. But for single-request latency at low concurrency, the architectural advantage of specialized silicon is real.

## Architecture: why a transformer-only chip could be fast
A GPU keeps flexible hardware for graphics, convolutions, recurrent nets and arbitrary kernels. **Why GPUs are good at inference**

Two things matter in inference, and they're different for the two phases of generating a response.

The first phase is prefill: processing your prompt all at once. That's a big batch of dense matrix multiplications, which is compute-bound — you want as many multiply-accumulate units as you can pack on a die, and GPUs have thousands of them in tensor cores. It also benefits from the huge memory bandwidth GPUs get from HBM stacks.

The second phase is decode: generating one token at a time. Here each token requires reading essentially all the model's weights again. For a 70-billion-parameter model at 16-bit, that's about 140 gigabytes of weight traffic per token, regardless of how much arithmetic you do. So decode is memory-bandwidth-bound, not compute-bound, and most of the GPU's flops sit idle. This is why an H100 at roughly 3 to 4 terabytes per second tops out in the low hundreds of tokens per second on a big model, and why batching helps so much: batching amortizes one weight read across many requests, which is why throughput-focused GPU serving is cheap even though single-user latency isn't great.

GPUs also win on flexibility. CUDA, cuDNN, TensorRT-LLM, vLLM, FlashAttention, speculative decoding, paged attention and quantization kernels all exist because the hardware is programmable. New model architectures, mixture-of-experts routing, multimodal encoders, diffusion — a GPU runs them the week they appear.
