Reference sketch (what a correct answer must contain):
An API is an interface one program offers to others (a web search service's HTTP endpoint, for example). A tool, for an LLM, is a function the model may ask to call, described by a name, a description and an argument schema; the surrounding software runs it and hands back the result. An MCP server speaks the Model Context Protocol, an open standard for offering tools (and resources and prompts) to any compatible client, and often wraps one or more APIs. Architecture: the model served locally; an agent loop that sends the conversation and tool list, runs any tool call, returns the result and asks again; an MCP server with a search tool (calling a search API or SearXNG) and a page-fetch tool (download, extract the main text, cap its size); summarizing done by the model itself from the returned text. Safeguards: a cap on tool rounds, timeouts, treating fetched text as untrusted (prompt injection), and caching.

Local LLMs running on Ollama or llama.cpp lack internet access by default. When users ask about current events, pricing, or anything time-sensitive, the model either hallucinates or refuses. Adding a web search tool through a structured API is the standard approach to AI search grounding — connecting LLM outputs to real-time web data to reduce hallucinations. The Scavio API returns structured JSON that fits in any local model's context window (600-800 tokens per result set vs 4,000+ for raw HTML). This tutorial wires a search tool into an Ollama agent using Python, so the model can autonomously decide when to search and ground its answers in live data. Works with any tool-capable model: Llama 3.1, Mistral, Qwen, DeepSeek, or Gemma.

## Prerequisites

- Ollama installed with a tool-capable model (llama3.1, mistral, etc.)
- Python 3.10+
- requests library installed
- A Scavio API key from scavio.dev

## Walkthrough

### Step 1: Define the search tool schema

Create a tool definition that tells the LLM what the search function does and what parameters it accepts. Ollama uses the OpenAI-compatible tool format.

``` import os import requests import json API_KEY = os.environ['SCAVIO_API_KEY'] SEARCH_TOOL = { 'type': 'function', 'function': { 'name': 'web_search', 'description': 'Search the web for current information. Use this when the user asks about recent events, prices, news, or anything you do not have up-to-date knowledge about.', 'parameters': { 'type': 'object', 'properties': { 'query': {'type': 'string', 'description': 'The search query'} }, 'required': ['query'] } } } ```

### Step 2: Implement the search function

The function calls the Scavio API and returns a condensed string of results that fits comfortably in the model's context window.

``` def web_search(query): resp = requests.post('https://api.scavio.dev/api/v2/google', headers={'Authorization': f'Bearer {API_KEY}', 'Content-Type': 'application/json'}, json={'query': query, 'gl': 'us'}) results = resp.json().get('organic_results', [])[:5] lines = [] for r in results: lines.append(f"{r['title']}: {r.get('snippet', '')} ({r['link']})") return '\n'.join(lines) if lines else 'No results found.' ```

### Step 3: Run the agent loop with Ollama

Send the user message to Ollama with the tool definition. If the model calls the tool, execute the search and feed the result back for the final answer.

``` def chat_with_search(user_message, model='llama3.1'): messages = [{'role': 'user', 'content': user_message}] resp = requests.post('http://localhost:11434/api/chat', json={ 'model': model, 'messages': messages, 'tools': [SEARCH_TOOL], 'stream': False }).json() msg = resp['message'] if msg.get('tool_calls'): for tc in msg['tool_calls']: if tc['function']['name'] == 'web_search': args = tc['function']['arguments'] result = web_search(args['query']) messages.append(msg) messages.append({'role': 'tool', 'content': result}) final = requests.post('http://localhost:11434/api/chat', json={ 'model': model, 'messages': messages, 'stream': False }).json() return final['message']['content'] return msg['content'] ```

### Step 4: Test with a real-time question

Ask the agent something it cannot answer from training data alone. The model should call web_search and synthesize the results.

``` answer = chat_with_search('What are the top trending Python libraries released in 2026?') print(answer) ```

## JavaScript Example

``` const API_KEY = process.env.SCAVIO_API_KEY; const SEARCH_TOOL = { type: 'function', function: { name: 'web_search', description: 'Search the web for current information.', parameters: { type: 'object', properties: { query: { type: 'string', description: 'Search query' } }, required: ['query'] } } }; async function webSearch(query) { const r = await fetch('https://api.scavio.dev/api/v2/google', { method: 'POST', headers: { 'Authorization': `Bearer ${API_KEY}`, 'Content-Type': 'application/json' }, body: JSON.stringify({ query, gl: 'us' }) }).then(r => r.json()); return (r.organic_results || []).slice(0, 5) .map(r => `${r.title}: ${r.snippet || ''}`).join('\n') || 'No results.'; } async function chat(userMsg, model = 'llama3.1') { const messages = [{ role: 'user', content: userMsg }]; let resp = await fetch('http://localhost:11434/api/chat', { method: 'POST', body: JSON.stringify({ model, messages, tools: [SEARCH_TOOL], stream: false }) }).then(r => r.json()); if (resp.message.tool_calls) { for (const tc of resp.message.tool_calls) { const result = await webSearch(tc.function.arguments.query); messages.push(resp.message, { role: 'tool', content: result }); } resp = await fetch('http://localhost:11434/api/chat', { method: 'POST', body: JSON.stringify({ model, messages, stream: false }) }).then(r => r.json()); } return resp.message.content; } chat('Latest AI news in 2026?').then(console.log).catch(console.error); ```

I built a web-search-API cost calculator this week — the kind of tool you make when you're about to wire a retrieval layer into an agent and don't want to guess. Provider | Model | Rate
Serper | Flat per-query, prepaid credit pack | ~$1 / 1,000 queries
Brave Search API | Per-query, $5/mo account credit | $4-5 / 1,000 queries
Exa | Per-search, depth surcharge | $7 / 1,000 (standard), $12 / 1,000 (deep)

Serper and Brave are the two that behave like normal APIs — you pay roughly linearly for what you use. Exa and Tavily aren't really pricing "search," they're pricing a small AI pipeline: a neural ranking layer, and optionally full-page content extraction cleaned up for an LLM prompt. SerpAPI doesn't price per query at all — it sells eight fixed plans, and you pay for the smallest one that covers your volume, whether you use 1% of it or 100%.

Exa's standard search runs $7/1,000 queries. Ask it to crawl deeper for a harder query and that jumps to $12/1,000 — a depth surcharge, not a flat rate. Tavily runs on credits: a plain search is 1 credit, but a search that also fetches and cleans the full page content (strips nav, ads, boilerplate, hands you something you can chunk and embed straight away) costs 2 credits. Both vendors give you something Serper and Brave don't: at 20,000 queries/month with extraction on, Exa is $240 and Tavily is $312 — expensive next to Serper's flat $20, until you count the engineering hours you'd spend writing and re-writing your own HTML cleaner every time a site redesigns its markup. If the job is RAG ingestion, that premium is usually still cheaper than maintaining a parser.

If you only need links and snippets — you're doing your own re-ranking, or feeding results to your own LLM without needing pre-cleaned page text — the extraction layer is dead weight, and Serper wins by a wide margin at almost any volume. Brave sits in the middle: still a flat per-query rate, no extraction tier, but roughly 4-5x Serper's price with a small $5/month credit that barely moves the needle past a thousand queries. SerpAPI is the odd one out — no per-query rate, just eight step-tier plans (Free 250, then $25/1,000, $75/5,000, $150/15,000, $275/30,000, $725/100,000, $1,475/250,000, $2,750/500,000).
