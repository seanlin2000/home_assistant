ASSISTANT: Quantizing a model means storing its 70 billion weights in fewer bits than the format they were trained in. A model trained at 16-bit floating point uses two bytes per weight, so quantization replaces each weight with a small number of discrete values, like a 4-bit number that can take only sixteen values or a 2-bit number that can take just four, and keeps a few extra bookkeeping values per group of weights so you can roughly reconstruct the original precision when doing the math.

The memory math, assuming the 70 billion weights and ignoring overhead: at 4 bits per weight that is 280 billion bits, which works out to about 35 gigabytes of RAM. At 2 bits per weight it is half of that, about 17 and a half gigabytes. For comparison, the same model at 16-bit precision needs roughly 140 gigabytes, which is why quantization is what makes a 70-billion-parameter model runnable on a laptop or a single workstation GPU at all.

The trade-offs are a few different things. The obvious one is accuracy: you are rounding each weight, and with only four possible values at 2 bits you discard a lot of information, so outputs get measurably worse, often noticeably so, while 4-bit with a good scheme like GPTQ or AWQ typically degrades quality by a small but real amount. The second trade-off is compute: the arithmetic unit does not naturally do 4-bit or 2-bit math, so the model has to dequantize on the fly, which can make decoding slower per token than a well-supported 16-bit model despite the memory savings. Third, quantized models tend to be more brittle to long prompts, rare words, and fine-tuning, and some features like certain attention patterns are more sensitive than others, which is why mixed-precision schemes keep critical parts at higher precision. Finally, in practical terms, the 4-bit checkpoint is roughly four times smaller to download and fits in consumer hardware, while 2-bit is usually only worth it when you are memory-starved and can accept a meaningful quality drop.
