Reference sketch (what a correct answer must contain):
GPUs run thousands of simple cores in parallel with dedicated matrix units and very high memory bandwidth (HBM), and neural networks are mostly matrix multiplication; token-by-token generation is largely limited by memory bandwidth. NVIDIA's software stack (CUDA) is a large part of the advantage. An ASIC is a chip built for one kind of job (Google's TPU), more efficient but less flexible. Specialized inference processors go further for serving models, for example large on-chip SRAM instead of external memory (Groq), wafer-scale chips (Cerebras), or chips hard-wired for transformers (Etched). A specialized chip can win when the model architecture is stable and matches the chip, when the workload is high-volume and fixed, when latency per token matters most, or on cost or power per token; it loses when models change, when flexibility or training matters, or where software support is thin.

## Sohu Architecture: The Transformer-Only Bet
### Fixed-Function Transformer Units
Transformer attention requires three core operations at each layer: computing query, key, and value projections; running multi-head attention across the KV cache; and passing results through a feed-forward network. On a GPU, each of these is a CUDA kernel that can be swapped out for a different implementation. PagedAttention, FlashAttention-2, and FlashAttention-3 are all software optimizations that improve how attention is computed on general-purpose hardware.
On Sohu, these operations are hardwired as static circuits. The chip does not have a general matrix multiply unit that runs attention software. It has physical circuits that implement the attention computation directly. This removes all of the overhead from kernel launch latency, memory allocation, and scheduler decisions. It also means the chip cannot run any computation that does not map to transformer attention. There is no way to compile a convolution, an SSM scan, or a diffusion U-Net step onto Sohu because there are no programmable units to target.
### On-Chip Memory Design
Sohu's throughput advantage comes primarily from memory bandwidth. The bottleneck for autoregressive decode on GPUs is KV cache reads: each new token requires reading the full KV cache from HBM. The H100 SXM5 has 80 GB of HBM3 with 3.35 TB/s of bandwidth. Every token generation step is bounded by how fast the model can read those KV cache values.
According to Etched's published materials and industry reporting, Sohu uses 144GB of HBM3E per chip with approximately 1.8x the memory bandwidth of an H100 SXM5. Our HBM3e vs HBM4 vs HBM4e inference guide covers what that same HBM3E generation delivers on GPUs, so you can see how much of Sohu's bandwidth edge comes from the memory type versus the fixed-function architecture. That gives Sohu more memory capacity than an H100 (80GB) at roughly 1.8x the H100's 3.35 TB/s bandwidth, using the same HBM architecture that GPUs use rather than replacing it with on-chip SRAM. The Groq 3 LPU takes a fundamentally different route: 500 MB of on-chip SRAM per chip achieves 150 TB/s bandwidth but with very limited context window capacity. Sohu's throughput advantage over GPUs comes from architectural specialization of transformer attention patterns built on top of standard HBM3E, not from a SRAM-based design like Groq. Multi-chip configurations are still required for large model weights since even 144GB fills quickly with 70B+ parameter models at full precision.

ASSISTANT: GPUs are effective at AI inference for one structural reason: a neural network forward pass is mostly a very large number of small, identical multiply-and-add operations on matrices, and a GPU is essentially a few thousand arithmetic units wired to do exactly that, in parallel, at low precision. Modern NVIDIA chips add tensor cores that do a small matrix tile per instruction, and they can run the whole pass in FP16, FP8, or INT4 instead of FP32, which roughly doubles or quadruples the useful throughput for a fraction of the energy. That part is the easy half of the story.

The hard half is memory, and it is worth being clear about, because it is where the specialized chips are actually attacking. Once a model's weights are loaded, generating one token means reading those weights again, plus reading the growing key-value cache. On an H100, the high-bandwidth memory next to the chip moves somewhere around three and a half terabytes a second, and a seventy-billion-parameter model in eight-bit precision is seventy gigabytes of weights, so the arithmetic units spend much of their time waiting for data. Inference on a single user request is memory-bound, not compute-bound. This is why batching helps GPUs so much on a server: amortize one weight read across many requests, and you become compute-bound again. The corollary is that GPUs are excellent at throughput and mediocre at the latency of a single reply, and much of the tuning work in the GPU world, FlashAttention, paged attention, speculative decoding, TensorRT-LLM, is about reducing memory traffic per token rather than adding flops.

An ASIC, applied specifically silicon, trades that flexibility for fixed-function circuits. The clearest 2026 example is Etched's Sohu, a transformer-only chip that came out of stealth in June 2026 with working silicon. Attention, the key-value cache lookups and the feed-forward multiply are hardwired as static circuits rather than written as CUDA kernels. You lose kernel launch overhead, scheduler decisions and dynamic memory allocation entirely, so you use a far higher fraction of the die. Etched claims a single eight-chip server does about five hundred thousand tokens a second on Llama seventy-billion, which works out to around sixty-two thousand tokens per chip, against roughly seven hundred for one H100 on a single stream. That comparison is Etched's own number, with no independent benchmark published as far as I can find, so treat it as a claim. What is certainly true is the cost: a chip built only for transformer attention cannot run a convolution, a diffusion U-Net, a state-space model, or the dynamic expert routing that mixture-of-experts models like DeepSeek use. A model architecture shift strands the hardware.

Specialized inference processors like Groq's LPU and Cerebras's wafer-scale engine sit in between, and they solve the memory wall rather than the arithmetic. Groq keeps weights in on-chip SRAM with deterministic, statically scheduled execution, so there is no runtime scheduler at all. One chip has only about five hundred megabytes of SRAM, but the on-chip bandwidth is on the order of a hundred and fifty terabytes a second, so you string many chips together to hold the model. Cerebras goes the other way, putting an enormous amount of on-chip memory on a single wafer, reported at around forty-four gigabytes, so a whole model can stay resident. Independently measured numbers in 2026 put Groq around four to five hundred tokens a second on a one-hundred-twenty-billion model and Cerebras near three thousand, against perhaps a few hundred on equivalent NVIDIA hardware, with time-to-first-token under a hundred milliseconds versus four to six hundred on a GPU.

So when does a specialized chip win? Four conditions have to line up. First, latency is the product: voice agents, live captioning, real-time translation, coding assistants, and long agent chains where a small per-step delay compounds across dozens of steps. Second, the model is dense transformer decode, not multimodal, not MoE with dynamic routing. Third, and this is the one people forget, the model you actually want is available and well-supported on that platform, which means giving up your custom CUDA kernels and your PyTorch flexibility for the vendor's compiler and toolchain. Fourth, you have enough sustained volume to absorb the migration cost and, in many cases, a capital purchase, since unlike an H100 you generally cannot rent these chips on demand at a comparable hourly price.

And when does the GPU win? Almost everywhere else. Most inference spend is batch or near-batch: classification runs, embeddings, overnight summarization, bulk generation. There the metric is cost per token at high concurrency, and commodity GPU capacity is cheap per token and easy to get. GPUs also absorb new architectures within a software update, which matters a lot in a field where the dominant attention pattern has changed more than once in the last few years. A useful rule is that a GPU is a computer you program, an ASIC is a program you manufacture.

One 2026 wrinkle worth knowing: NVIDIA paid roughly twenty billion dollars in late December 2025 for a non-exclusive license to Groq's LPU technology and brought Groq's founder and most of its engineering team in-house, with NVIDIA-branded Groq 3 LPU hardware appearing in subsequent roadmaps. That both validates the specialized approach and narrows the gap from inside the incumbent, so the honest conclusion is that the specialized-chip advantage is real but narrow, concentrated on low-latency dense transformer serving at volume, while the generalist GPU keeps the broader market on the strength of its software.
