# Exchange 1

USER: Imagine I want to build a private, locally hosted voice assistant that can answer general questions, search the web, control smart-home devices, and have natural conversations. I have a $1,000 hardware budget. Propose an architecture, explain the components, identify the biggest limitations, and prioritize what I should build first.

ASSISTANT: Here's a lean build. For compute, a used GPU card — something like an RTX 3060 or 4060 with 12 gigabytes — plus a modest PC runs a local large language model and keeps you under budget, leaving room for a decent microphone and speakers.

The pipeline is four stages. Wake-word and voice-activity detection, then speech-to-text with a local model, then the language model that plans and answers, then text-to-speech to reply. Smart-home control and web search become "tools" the model calls by name, using Home Assistant or Matter locally and a search API for the web.

The biggest limits: a mid-range GPU means a smaller model, so reasoning and follow-up quality will trail commercial assistants; the full speech loop adds real latency; and local web search is weak, so you'll likely keep one hosted search call.

Build the conversation loop first — text-in, voice-out — because every other feature rides on it. Then add one smart-home command, then search.
